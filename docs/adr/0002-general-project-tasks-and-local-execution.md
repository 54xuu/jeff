# ADR 0002：项目群使用通用任务与本机执行记录

- 状态：已采纳
- 日期：2026-10-08

## 背景

项目工作台把销售、宣传选题、素材审批和报告模板等专用流程放进每个项目群。这些业务不能代表所有任务，也没有已保存的用户数据需要迁移。项目任务还缺少独立目标字段、统一启动入口和人工验收闭环。

## 决策

- 移除项目工作台及其专用业务、IPC、工具和界面；直接删除旧 `workspace_state` 列，不做无数据价值的迁移或归档。
- 通用任务由标题、三个可选且独立的字段（目标、任务描述、验收标准）、负责人和通用调度信息组成。业务领域内容由用户写在任务要求中。
- 保存任务不启动执行。用户点击“开始执行”后，有负责人时交给该成员；未指定时由项目群群主协调。
- 每个任务使用独立话题。任务定义和验收事实属于可同步的结构化数据；单机执行记录、运行状态、会话和 Prompt 快照只保存在本机。
- Agent 提交结果后进入待验收；只有用户能通过或退回。任务要求改变后，旧提交不能再作为当前要求的验收依据。
- Prompt 按个人身份、项目事实、群规则、成员职责、记忆、AGENTS.md 与当前任务分别标明含义和作用域；群内普通讨论、委派、子任务和任务执行复用群上下文。私聊不携带项目群上下文。

## 结果

项目群资料聚焦通用管理，销售或其他具体工作继续由普通任务、工具和技能完成。任务可以在多设备间同步定义和验收结果，但任务不会因同步而自动执行；运行详情只在实际执行它的电脑上可见。

删除已发布的专用能力属于破坏性变更，实施版本按项目 SemVer 规则升为 2.0.0。
