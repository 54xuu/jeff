# ADR 0004：思源作为 Jeff 知识库，连接凭据留在本机

- 状态：已采纳
- 日期：2026-10-09

## 背景

Jeff 需要在对话中检索和读取思源资料，并在用户明确要求时创建文档或追加内容。原有 `siyuan-*` skills 各自保存 Kernel 地址和 Token，微信读书与季报工作流还带有独立客户端，导致不同入口可能连到不同服务器、使用不同写入规则。

## 决策

- 思源是 Jeff 的外部知识库。Agent 对历史资料、已有项目知识的相关问题主动检索，也响应用户明确的查询要求；项目群先使用本群绑定范围，结果不足时可扩展至全库，并返回可引用的标题、路径和文档 ID。
- 搜索、读取和写入统一由 `packages/core/src/siyuan/` 的客户端及 Jeff 工具桥执行。工具从 Jeff 当前会话解析项目身份，不接受模型自报的项目 ID。
- 仅在用户明确要求写入时执行。写入位置顺序是用户指定位置、项目群绑定位置、全局默认位置、询问用户。第一阶段只支持创建和文末追加；不提供修改、覆盖或删除工具。同名路径冲突时拒绝覆盖。
- Kernel 地址与 API Token 保存在当前电脑 Jeff 数据库 KV 的 `integration:siyuan`；配置读回只暴露 Token 是否已设置。凭据不进入 WebDAV payload、备份、手机请求、Agent 参数、日志或知识库正文。
- 全局归档目标和项目群绑定属于可同步的结构化设置，只同步笔记本/父文档 ID；不增加独立备份入口。项目工作区路径仍按现有约定只保存在本机。
- 手机通过绑定电脑的现有加密 IPC 使用思源。手机可读取笔记本/文档目录并配置项目归档位置，但不能读取或保存 Kernel Token。
- `jeff-weread-siyuan` 与 `jeff-cornley-work` 保留原业务流程，思源读写只调用 Jeff 内置工具；不再复制 Kernel 客户端或维护 `siyuan.env`。Ubuntu、Windows 的三个基础 `siyuan-search`、`siyuan-read`、`siyuan-write` skills 在替代链路验证后移除。

## 结果

Jeff 对思源连接和写入位置有一个明确所有者，连接凭据与可同步的归档策略分离。失效连接、缺少归档位置或同名文档均停止写入并返回原因，避免静默写入错误笔记本或覆盖已有内容。
