# 定时任务（Jeff v1.8.0+）

定时任务 = **到点自动向某个会话发一条消息，并让对方回复**。
适用场景：每天早上 8 点在项目群里问「今天的病区动态」（护士长 agent 发起、成员 agent 各自汇报）；
或每天早上 8 点让「AI 资讯助手」报最新 AI 资讯。

## 使用

- 左侧导航「定时」进入管理页；也可以直接对小杰说「每天早上 8 点让资讯助手报最新 AI 资讯」，由它建任务。
- 每条任务包含：任务名、目标（某个智能体的私聊 / 某个项目群）、cron 表达式、触发时要说的话、错过处理策略。
- 卡片上可：立即执行一次、启用/停用、编辑、删除、查看运行历史（成功/失败/补跑/跳过 + 耗时 + 失败原因）。

## cron 表达式

5 段式，**本机时区**：`分 时 日 月 周`（周 0/7 = 周日）。

| 写法 | 含义 |
|------|------|
| `0 8 * * *` | 每天 08:00 |
| `30 8 * * 1-5` | 工作日 08:30 |
| `0 9 * * 1` | 每周一 09:00 |
| `0 9 * * 0,6` | 周末 09:00 |
| `0 * * * *` | 每小时整点 |
| `*/30 * * * *` | 每 30 分钟 |
| `0 9 1 * *` | 每月 1 日 09:00 |

新建/编辑弹窗里有常用模板一键填充，并实时显示人性化描述与「下次触发时间」。
日与周同时限定时按 cron 惯例取「或」（命中其一即触发）。

## 错过处理（关键）

Jeff 没开机时错过的触发按任务选择：

- **开机后补跑一次**（`catchup`，默认）：重要任务用（当天的病区动态不能漏）。
- **直接跳过**（`skip`）：资讯类等不重要任务用，避免开机后被一堆迟到消息打扰。

只补跑「最后一次错过」，不会把历史欠账全部补一遍。

## 执行语义（实现约束）

- **私聊**与用户手动聊天**共用同一会话**：早报类场景需要跨天记忆连续性（昨天报过什么，今天能接着聊）。
- **群聊**走与手动发消息完全相同的协作链路：群主（leader）收到后按成员 @ 分派，成员回合执行完 leader 会做总结。
- 触发动作是阻塞式长任务（私聊一轮最长 600 秒、群流水线最长 30 分钟），因此调度器**并发上限为 2**，多个任务同刻到点会排队执行。
- 同一任务上一轮还在跑时又到点 → **跳过本次**并记 `skipped`，不堆叠。
- **失败不自动重试**：只记录失败原因，由用户在卡片上手动「立即执行」。
- 目标被删除（智能体/项目群）→ 任务**自动停用**并在运行记录里写明原因。
- 需要人工确认的权限（如需审批的文件操作）在无人值守场景**不会挂起**：Jeff 的引擎配置对工具调用默认放行。
- 定时任务定义会随 WebDAV 同步；`next_run_at` 不跨设备搬运，由各设备按 cron 表达式自行推算。运行历史（`cron_run`）属本机日志，不参与同步。

## 智能体侧工具

| 工具 | 用途 |
|------|------|
| `jeff_cron_create` | 建任务（名称、目标、cron、提示词、错过策略） |
| `jeff_cron_list` | 列出所有任务与上次运行状态 |
| `jeff_cron_update` | 改时间/提示词/错过策略、启用停用 |
| `jeff_cron_delete` | 删除任务（软删除） |
