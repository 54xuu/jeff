# 定时任务（Jeff v1.8.0+）

定时任务 = **到点自动向某个会话发一条消息，并让对方回复**。
适用场景：每天早上 8 点在项目群里问「今天的病区动态」（护士长 agent 发起、成员 agent 各自汇报）；
或每天早上 8 点让「AI 资讯助手」报最新 AI 资讯。

## 使用

- 左侧导航「定时」进入管理页；也可以直接对小杰说「每天早上 8 点让资讯助手报最新 AI 资讯」，由它建任务。
- 每条任务包含：任务名、目标（某个智能体的私聊 / 某个项目群）、cron 表达式、触发时要说的话、错过处理策略。
- 卡片上可：立即执行一次、启用/停用、编辑、删除、查看运行历史（成功/失败/补跑/跳过 + 耗时 + 失败原因）。

## cron 表达式

5 段式，**本机时区**：`分 时 日 月 周`（周 0/7 = 周日）。

| 写法 | 含义 |
|------|------|
| `0 8 * * *` | 每天 08:00 |
| `30 8 * * 1-5` | 工作日 08:30 |
| `0 9 * * 1` | 每周一 09:00 |
| `0 9 * * 0,6` | 周末 09:00 |
| `0 * * * *` | 每小时整点 |
| `*/30 * * * *` | 每 30 分钟 |
| `0 9 1 * *` | 每月 1 日 09:00 |

新建/编辑弹窗里有常用模板一键填充，并实时显示人性化描述与「下次触发时间」。
日与周同时限定时按 cron 惯例取「或」（命中其一即触发）。

## 错过处理（关键）

Jeff 没开机时错过的触发按任务选择：

- **开机后补跑一次**（`catchup`，默认）：重要任务用（当天的病区动态不能漏）。
- **直接跳过**（`skip`）：资讯类等不重要任务用，避免开机后被一堆迟到消息打扰。

只补跑「最后一次错过」，不会把历史欠账全部补一遍。

## 执行语义（实现约束）

- **私聊**：每个定时任务一条独立 opencode 会话（kv `session:cron:<taskId>`），与用户手动聊天的 `session:private:<agentId>` 分开。同一任务反复触发复用自己那条（早报跨天连续）；不同任务互不污染上下文。
- **群聊**：每个定时任务一条独立话题（kv `cron:thread:<taskId>`），创建时**不切换**用户当前正在看的话题。消息带 `meta.cron_task_id`，气泡上有「⏱ 定时」标签。
- 触发动作是阻塞式长任务（私聊一轮最长 600 秒、群流水线最长 30 分钟），因此调度器**并发上限为 2**，多个任务同刻到点会排队执行。不同智能体/不同项目群的任务可并行；同一项目群内因共享工作空间仍串行（防文件/git 竞争），但会话已经隔离。
- 同一任务上一轮还在跑时又到点 → **跳过本次**并记 `skipped`，不堆叠。
- **失败不自动重试**：只记录失败原因，由用户在卡片上手动「立即执行」。
- 目标被删除（智能体/项目群）→ 任务**自动停用**并在运行记录里写明原因。
- 删除任务是**软删除**（留墓碑给 WebDAV 同步，别的设备才知道这条没了）：调度器只取
  `deleted_at IS NULL AND enabled = 1` 的任务，所以删掉后不会再触发、卡片也从列表消失；误删要趁同步把墓碑传出去之前反悔，
  实在需要找回时手工编辑 WebDAV 上的 `cron_tasks.json`（墓碑行里定义内容仍在：把该行 `deletedAt` 改回 `null`、`updatedAt` 调到最新，下次同步即恢复）。
- 需要人工确认的权限（如需审批的文件操作）在无人值守场景**不会挂起**：Jeff 的引擎配置对工具调用默认放行。
- 定时任务定义会随 WebDAV 同步；`next_run_at` 不跨设备搬运，由各设备按 cron 表达式自行推算。运行历史（`cron_run`）属本机日志，不参与同步。

## 智能体侧工具

| 工具 | 用途 |
|------|------|
| `jeff_cron_create` | 建任务（名称、目标、cron、提示词、错过策略） |
| `jeff_cron_list` | 列出所有任务与上次运行状态 |
| `jeff_cron_update` | 改时间/提示词/错过策略、启用停用 |
| `jeff_cron_delete` | 删除任务（软删除） |

这组工具**只给小杰**：定时任务是「替用户安排无人值守的自动执行」，与 `jeff_agent_*` 同级，
不下放给项目群里可能接触不可信内容的 worker 智能体（它们在 agent 定义里被写成 `jeff_cron_*: false`）。

小杰建任务时会先问清四件事：**时间、目标、说什么、错过怎么办**，确认后调 `jeff_cron_create`。
`target_id` 要的是 id 而不是名字，小杰会先用 `jeff_agent_list` / `jeff_project_list` 查出来再传；
它的指令里也写明了「不要自己发明时间」——不确定就问。

## 同步（没有独立的备份/恢复入口）

定时任务定义（`cron_task`）作为实体参与 WebDAV 同步（含软删除墓碑，与智能体/项目同一套 LWW 规则），
**不设**「立即备份 / 从备份恢复」按钮：它是纯配置数据（一条记录几行 JSON），不存在 skills / 插件目录那种「文件太多、整目录同步太慢」的问题，
所以只走「立即同步」的双向合并。判定标准与理由见仓库 `AGENTS.md` 的「备份与恢复入口（硬性约定）」。
合并按 `updatedAt` 取新（本机改过的排期不会被远端旧记录覆盖），合并后按本机 cron 表达式重算 `next_run_at`。
运行历史（`cron_run`）是本机日志，不参与同步，也不进任何备份。

**实现约束（踩过坑，别改回去）**：`cron_task.updated_at` 是同步用的 LWW 版本号，**只有「定义被改」才该推进**。
调度器推进 `next_run_at`（`setNextRun`）、回填 `last_run_at`（`markRun` / `setLastRun`）、以及同步落地时重算排期，
都属于本机执行状态，**一律不碰 `updated_at`**——否则「跑了一次任务」或「只是接收了一次同步」就会被当成「改过定义」，
以更新的时间戳顶掉另一台机器上真实的编辑（v1.8.5 修的真 bug，回归用例在 `packages/core/tests/cron-sync.test.ts`）。

## 排查

- 任务没触发：先看卡片上的「下次触发时间」与启用开关，再看运行历史里的 `missed` / `skipped` 记录。
- 应用上次是被强制关掉的：启动时会把还挂着的 `running` 记录收尾为 `failed`（原因写「应用退出导致本次执行中断」），
  避免出现永远转圈的僵尸记录。
