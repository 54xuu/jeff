# 内置浏览器（Jeff v1.8.0+）

在 Jeff 界面右侧开一个浏览器面板，**人和智能体用同一个页面**：你手动点，或让智能体模拟人操作。

## 打开方式

- 顶部菜单「显示 → 内置浏览器」（快捷键 `Ctrl/Cmd+Shift+B`）
- 左侧导航栏底部的地球图标
- 让智能体调用 `jeff_browser_*` 工具时**自动打开**（面板未打开会自动唤起并导航）
- 插件页「首页」按钮（打开插件的 homepage）

面板是右侧独立分栏，**不改变原有界面**：可拖拽左边缘调宽度、可一键关闭（关闭即销毁 webview，不留后台进程）。

## 三栏布局（会话列表 / 对话区 / 内置浏览器）

- **拖拽调宽**：分栏交界处有一条 6px 热区，鼠标靠近才显形（亮成绿色竖线）；按住拖动即可改宽度，
  双击恢复默认宽度。拖拽期间会盖一层透明遮罩——鼠标划过 webview 时事件会被 guest 页面吃掉，
  没有遮罩则「往右拖窄浏览器」会中途断掉。
- **显示 / 隐藏**：左栏与浏览器面板都能收起。hover 分栏线时中间浮出箭头按钮即可收起；
  左栏收起后对话区左边缘留一条细条，点一下放回来。快捷键 `Ctrl/Cmd+B` 开关会话列表，
  菜单「显示」里另有「会话列表 / 内置浏览器 / 重置窗口布局」三项。
- **默认宽度**：浏览器面板首次打开取「窗口宽度的 42%，且不小于 520px」，最大可拖到只剩 360px 对话区；
  会话列表默认 280px（范围 200–480）。宽度与显隐记在本机（localStorage），不参与跨设备同步。
- 智能体调整不了布局，也不受布局影响：面板被拖窄、左栏被收起时，`jeff_browser_*` 照常工作。

## 面板能力

- 工具栏：后退 / 前进 / 刷新 / 地址栏 / 在系统浏览器打开 / 关闭
- 地址栏输入省略协议的地址（如 `localhost:5173`）会自动补 `https://`
- 上次访问的地址会被记住
- 只允许 `http`/`https`；弹窗被拦截、页面权限请求默认拒绝

## 智能体工具

任意智能体都可以控制这个浏览器（这就是「插件首页 + 智能体代操作」的实现基础）：

| 工具 | 作用 |
|------|------|
| `jeff_browser_navigate` | 打开网址并等待加载完成，返回真实地址与标题（**加载失败会报错**，不会假报成功） |
| `jeff_browser_get_content` | 读取页面标题/地址/可见文本/**可交互元素清单**（找按钮、输入框时先调它） |
| `jeff_browser_click` | 点击元素：优先 CSS 选择器，也可按可见文字匹配 |
| `jeff_browser_type` | 向输入框键入文字（用原生 setter + input/change 事件，兼容 React 等受控组件），可选回车提交；`<select>` 下拉框按 value 或可见文字选项 |
| `jeff_browser_upload` | 把**本机文件**放进页面的 `<input type=file>`（内容由主进程读盘后以 base64 下发；只负责「选中」，提交还要再点提交按钮） |
| `jeff_browser_get_console` | 读当前页面采集到的错误：控制台 `console.error/warn`、未捕获异常、主文档加载失败、**子资源加载失败**（图片/脚本/接口 404、域名解析失败）；可按级别过滤 |
| `jeff_browser_screenshot` | 截图并把 PNG 存到 `~/.jeff/workspace/browser-shots/`，返回文件路径 |

关于截图：结果是一个**文件路径**而不是内联图片。支持视觉的模型可以直接读取该文件看图；
不支持看图的模型请改用 `jeff_browser_get_content` 读页面文本（工具说明里也会这样提示）。

关于错误采集：面板工具栏的红色角标与 `jeff_browser_get_console` 读的是**同一份缓冲**（上限 200 条），
导航开始时会清空（上一页的错误不记到新页面头上）。控制台条目分四级：`error`（含未捕获异常）、
`warning`、`info`、`load`（加载类失败）。两条采集来源：

- 渲染层 webview 的 `console-message` 事件（Console API 调用与未捕获异常）；
- **主进程**在该面板专属分区（`persist:jeff-browser`）上挂的 `webRequest`：子资源 404 / 网络失败
  不会走 `console-message`，只能在主进程看到。应用自身的网络请求不在这个分区里，不受影响。

## 表单类任务的标准打法（实测有效）

1. `jeff_browser_get_content` 看有哪些元素（拿到选择器/文案）
2. `jeff_browser_type` 填文本与下拉框，`jeff_browser_upload` 选文件
3. `jeff_browser_click` 点「提交/下一步」
4. `jeff_browser_get_console` 确认没有报错；必要时再 `get_content` 读提交结果

三步向导这类多步表单**不需要**一次调完：每点一次「下一步」都重新 `get_content` 看新出现的元素即可。

## 几个实现取舍（排查问题前先读）

- **不引入 Playwright/Puppeteer**：控制走 Electron webview 自带能力（`executeJavaScript` 做 DOM 查询与点击、
  `capturePage` 截图、`sendInputEvent` 键入），不额外背一个浏览器内核依赖。
- **就绪判断用「探测」而不是事件**：实测存在页面已加载（`did-navigate` 都到了）但 `dom-ready` 未触发的情况，
  只靠事件会永久卡在未就绪。现在通过试调一次 webview 方法来判断可用性，失败就重试。
- **动作有超时**：主进程侧每个请求 30 秒超时（面板关闭或页面无响应时 agent 会收到明确错误，而不是一直等）。
- **窗口不可用时立即失败**：主窗口已关闭时下发即报错，不会静默等待。
- **单控制者**：人和 agent 共用同一个页面，谁后操作以谁为准（没有并发隔离，这是刻意选择——便于协作演示与排障）。
