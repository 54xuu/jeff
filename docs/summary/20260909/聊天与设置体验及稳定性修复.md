## 二、代码审查发现并修复的缺陷

### 4.1 项目群 thread / stream / stop 归属（最严重）

- **根因**：流式事件、system 公告、停止操作都只按 `projectId` 归属，切换会话（thread）会让旧会话的流式气泡 / 公告串进新会话，停止可能 abort 错会话。
- 修复（`packages/core/src/orchestrator/group.ts` 等）：
  - `GroupChat` 新增按项目的运行态（冻结发起时 `threadId`、当前 `sessionId`、`cancelled`）；停止改为 `GroupChat.abort()`：标记取消（未开始的 worker 回合与最终总结不再执行）并精确 abort 当前会话；`JeffCore.abortGroup` 无在途时才回退旧的 last-session 兜底。
  - `addSystemMessage` 增加可选 `threadId` 参数，流水线公告显式写入原 thread。
  - session 元数据带 `threadId`，`chat-stream` / `group-updated` 事件携带 `threadId`；渲染层群历史改为 `{ threadId, messages }`，`GroupWindow` 不渲染异 thread 的流式气泡，`store` 收到异 thread 完成事件不刷新当前窗口。
  - 生成中禁止新建 / 切换 / 删除会话：core 侧抛错（`newGroupThread` / `activateGroupThread` / `deleteGroupThread`），UI 侧 `GroupInfoDrawer` 接 `busy` 禁用相关按钮并提示「生成中不可切换会话」。
  - `deleteThread` 清理指向被删 thread 的 last-session KV 指针（防 abort 已删除会话 / `lastGroupAgentId` 误判）。
  - **二级派发文本丢失**：派发队列由 `agentId[]` 改为 `{agentId, source}[]`，worker 二级转派时下游拿到转派者的实际任务说明（原实现回退到最初用户输入）；二级转派 prompt 标注「转派」来源。
  - `Delegator`（jeff_delegate）同样冻结 `threadId`。

### 4.2 私聊会话竞态与停止语义

- `PrivateChat.ensureSession` 增加按 agent 的 in-flight 去重（并发 send / 新会话不再建出多个远端 session、KV 指针不再互相覆盖）。
- 用户主动停止：新增 `PrivateChatStoppedError`，`chatSend` IPC 映射为 `{ ok: true, stopped: true }`；UI 显示「⏹️ 已停止生成」而非「发送失败」。
- 「新会话」在生成中禁用（按钮 + store 双重防护），防止会话指针被切走后回复丢失、停止打到新会话。
- 发送失败不再被 finally 的历史刷新瞬间冲掉：失败时保留本地用户消息与失败原因气泡（成功/停止才重拉历史）；群聊同样处理。

### 4.3 项目成员 / 群主一致性（projectSave）

- `projectAgentRepo` 新增事务方法：`setLeader`（旧群主降 worker + 唯一 leader）、`replaceMembers`（完整成员快照：差集删除 + 群主必在群且唯一）。
- `projectSave` 重写：直接用 `create/update` 返回的 row 构造响应（修复重名项目按 title 回查返回错误项目）；成员校验（不存在 / 已删除即拒绝）；快照语义替换原来的「只增不删」。
- `projectAddMember` / `projectRemoveMember` 校验项目与智能体存在且未删除。

### 4.4 设置与上下文失败恢复

- 上下文预览（ChatWindow / GroupWindow）改 `catch/finally`：IPC 失败不再可能停留在永久「加载中」。
- `EngineSettings` TLS / 调试开关：保存中禁用 + 失败回滚 + 内联错误（原来乐观更新失败会假装已生效，且产生未处理 rejection）。
- 补齐 `IPC.contextPreview` 类型契约的 `model` 字段（与实际 payload 一致）。

### 4.5 群 @ 补全范围

- `GroupWindow` 的 @ 候选从「全局 agents」改为「当前项目群成员」（后端 `parseMention` 只路由成员，原实现会误导派发）。

### 4.6 Sidecar 生命周期

- 显式 `stop()` 取消已排队的自动重启 timer，并引入 `wantedRunning` 生命周期标志（stop 后不会再被旧 timer「复活」）。
- 健康检查加连续失败阈值（3 次 ≈ 45s）：进程在但 HTTP 持续不通的「假运行」会被杀掉并走既有 exit → 自动重启链路恢复；成功 ping 清零计数。
- 启动成功即清空 `lastError`（running 状态不再挂着历史错误；`EngineSettings` 页不会再「显示运行中却带旧故障」）。

### 4.7 版本一致性

- `APP_VERSION = '1.3.0'` 与包版本严重漂移（`appInfo.jeffVersion` 会报错误版本）：移至 `packages/core/src/version.ts` 单一来源并同步为 `1.7.12`；新增 `tests/version.test.ts` 强制四处一致（APP_VERSION + 根/core/desktop package.json）。

### 4.8 敏感信息

- `e2e/ui.spec.ts` 移除硬编码 MySQL 测试凭据（内网 IP / root 密码），改为 `E2E_MCP_MYSQL_JSON` 环境变量注入，未提供时跳过该段。
