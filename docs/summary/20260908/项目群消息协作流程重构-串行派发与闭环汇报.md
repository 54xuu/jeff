# 项目群消息协作流程重构：串行派发与闭环汇报

- 日期：2026-09-08
- 版本：v1.7.8（PATCH）
- 范围：`packages/core/src/orchestrator/group.ts`、`packages/core/tests/group.test.ts`

## 问题

项目群里发消息后，leader（群主）习惯把事情全部自己干完，没有形成真实的团队协作链路。正确流程应为：

> leader 收到消息拆解任务 → 把不同任务 `@` 给群里合适的 worker（按各自能力分工）→ worker 执行任务 → worker `@` leader 汇报 → leader 汇总验收后回复用户。

旧实现的原因：

1. 系统提示词写着「能自己答就答」，并要求派活必须调用 `jeff_delegate` 工具（在 leader 自己的会话里静默执行，群内不可见），导致 leader 大包大揽；
2. leader 回复文本里的 `@成员` 不会触发任何调度（仅用户消息支持 @ 直达）；
3. 群名册只有名字和 leader/worker 标签，leader 没有依据去分析「谁适合干什么」。

## 方案（经 grill-me 逐项确认）

| 决策点 | 结论 |
| --- | --- |
| 协作驱动机制 | 选项 A：基于群消息文本 `@` 的事件驱动流转（不是工具调用驱动），群聊记录如同真实团队群 |
| worker 能力识别 | 动态注入《群成员名册与技能清单》：把每个成员的 description / instructions 摘要写进 briefing，不做数据库/前端改造 |
| 并发 vs 串行 | 串行执行。并行会抢占工作空间文件/git 资源；不用 worktree（现阶段不做复杂化，且工作空间不一定有 git） |
| 直答 vs 派发边界 | 打招呼/寒暄/纯问答/群内仅 leader 一人 → 直答；执行型任务 → 必须拆解并 `@` 派发，禁止 leader 包揽 |
| 防死循环 | 单次用户消息全链路最多 5 步（`MAX_PIPELINE_HOPS`），超限后由 leader 直接汇总兜底 |

## 实现

### 1. 提示词重构（`buildBriefing`）

- 名册每行追加成员 `description` 与 `instructions`（截 150 字）摘要，形成技能清单；
- leader 指令改为四条规则：简单消息直答；执行型任务严禁包揽，必须对照技能清单拆解、按顺序 `@成员名 <子任务要求>` 派发；worker 汇报后由系统自动唤醒 leader 总结；
- worker 指令明确：收到指派全力执行，完成后必须以 `@<leader名> 汇报：<结果>` 格式公开汇报。

### 2. 串行流水线调度（`send` 重构）

- 抽出私有方法 `runTurn()`：驱动单个 agent 回合一轮（调 opencode → 落库 → 错误兜底 → 返回回复文本与是否被用户停止）；
- `send()` 变为编排器：
  1. 第一回合响应用户（默认 leader，@成员 直达）；
  2. `parseAllMentions()` 解析回复文本中全部 `@`（按出现顺序、去重、同位置最长名优先），生成串行执行队列；
  3. 逐个驱动 worker：`extractMentionTask()` 从 leader 消息中截取该 worker 名下的一段任务说明，拼上「群主指派 + 汇报格式要求」发给 worker 会话；
  4. worker 回复里 `@` 其他 worker 会续入队列继续串行执行；`@` leader 视为汇报；
  5. 队列执行完毕（或超限）后自动唤醒 leader：「系统通知：派发任务已全部汇报完毕，请验收并向用户给出最终总结」；
- 用户直连 `@worker` 时，worker 汇报 `@leader` 也会触发 leader 验收总结；
- 每步执行中/停止/失败沿用既有机制：流式上屏靠 sidecar 事件桥（`session.idle` → `group-updated`），用户点停止立即中断整条流水线，失败写系统消息并终止后续派发；
- 兼容说明：`jeff_delegate` 工具保留可用，但提示词不再引导 leader 使用，主链路改为 @ 消息驱动。

### 3. 测试

`packages/core/tests/group.test.ts` 新增/更新 7 个用例：多 @ 解析顺序与去重、最长名优先、任务说明切分、完整闭环（leader 拆解 → 开发 → UI 串行 → leader 总结）、用户直连 worker 的汇报闭环、5 步上限兜底、纯直答不触发总结回合。全量 `npm test` 102 通过。
