# 部署清理与构建产物保留

## 目标

在正式构建、部署入口中落实已确认的保留规则：Ubuntu 只删除可重建的明确构建目录；保留最新两个验收通过的三平台正式包和本轮候选包；Windows 在本轮 outcome/run ID 匹配且证据回传核验成功后清理本轮远端暂存与隔离数据，同时保留最近 3 份成功快照、最近 1 份失败快照和所有结果未知的快照。

## 实现

- 将仓库版本统一升至 `2.1.1`。`AGENTS.md` 写明正式入口、清理边界、快照保留策略与 `.tmp` 规则。文档提醒 Agent 使用脚本；真正执行由构建/部署入口和脚本负责。
- 新增 `scripts/clean-build-outputs.mjs`，只清桌面 `out` / 对应平台 unpacked、Mobile `dist` 和 Android build 输出；通过精确版本清单保留完整验收通过的回退包与当前构建候选包。Android `cap:sync` 清中间产物，`assembleRelease` 清旧版本 APK 并在 `preBuild` 清 Gradle 生成目录。
- 新增 `scripts/deploy-cleanup.mjs`，核验 run ID、outcome、证据回传状态和路径边界后清理部署暂存；只删本轮上传清单列明的精确包文件名，路径含符号链接时拒绝清理。共享暂存发现待处理 worker 请求时延期清理，`incoming` 中的其他包、自建脚本和场景文件不受影响。
- `deploy:windows` 校验 Windows 回传 outcome 与本地下载证据一致后调用清理；只有 Windows 安装及具名验收成功才登记本机验收版本并裁剪更旧包。签名 APK 增加包名、版本号、versionCode、签名校验与 SHA-256 输出。

## 验证

- 清理策略、路径边界、幂等性、入口接线和部署工具单测：`node --test scripts/clean-build-outputs.test.mjs scripts/deploy-cleanup.test.mjs scripts/deploy-windows.test.mjs`，26 项通过。
- `node --check`（清理器与部署器）及 `git diff --check` 通过。
- Windows 清理脚本隔离集成验证 7/7 通过；使用独立测试目录，测试结束后已删除该目录，没有触碰生产快照。
- 三平台正式回归、构建和 Windows 具名部署验收在后续 `npm run deploy:windows -- --target win11 --android auto --suite smoke` 中执行，结果待补。

## `.tmp` 盘点

不对混合用途 `.tmp` 做自动清理。当前可供人工确认的解包候选包括：`.tmp/deb-x`（约 653 MB）、`.tmp/nsis-payload`（约 1.1 GB）和 `.tmp/engine-design/nsis-payload`（约 205 MB）。`.tmp/deploy`（约 106 MB）是部署证据目录，`.tmp/agent-merge`（约 2.3 GB）是近期工作目录，均保留。
