# 版本号修改规则收紧

## 背景

版本号上升过快（短时间到 `1.7.0`）。原 AGENTS.md 把「新功能或功能重构」一律升 MINOR，过宽：修同步缺口 + 补 MCP 这类也会被当成 MINOR。

## 新规则（已写入根目录 `AGENTS.md`）

1. **默认 PATCH**；拿不准先问用户，不要自行升 MINOR/MAJOR。
2. **MINOR** 仅限「用户能说出多了一个功能」的独立可感知新能力。
3. **修 bug + 在已有能力上打补丁**（含把 MCP 塞进已有同步包）→ PATCH。
4. 纯文档 / 纯测试 / 只改 AGENTS.md → **不 bump**。
5. 同一会话 / 同一发版意图 → **只 bump 一次**。
6. bump 时机改为「要发版或本机安装验证时」，不在每个小改途中改版本号。

本次只改协作规范，**未再 bump** 版本号（仍为 `1.7.0`）。
