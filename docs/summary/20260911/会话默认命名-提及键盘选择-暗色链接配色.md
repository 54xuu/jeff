> 仓库版本：1.7.21 → **1.7.22** → **1.7.23**（两次都是 PATCH：既有功能的交互补齐、显示修正与入口重排，无破坏性变更、无独立新能力）
> 验证：core 单测 183 passed / 15 skipped；core 与 desktop 包级 `tsc --noEmit` 全绿；Playwright UI E2E 通过；
> Ubuntu deb + Windows exe 双平台产物级校验通过。

## 一、用户报告

1. 对话界面输入 `@` 后，只能用鼠标点选智能体，希望支持键盘 ↑↓ 选择。
2. AI 回复正文里的超链接在暗色主题下是暗蓝色，几乎看不清，要求换成亮蓝色。
3. 「会话记录」里的默认名称希望按 `{YYYYMMDD-HHmm}-{任务中文名称}` 模板命名（方便按时间+任务回忆）。

## 二、三个问题的根因

### 1. `@` 候选只有鼠标，没有任何键盘导航

`@` 提及只存在于群聊输入框（[`GroupWindow.tsx`](../../../apps/desktop/src/renderer/src/components/GroupWindow.tsx)），
候选面板是内联 JSX，每项只有一个 `onClick`；全渲染层当时搜不到任何 `ArrowUp/ArrowDown/activeIndex`
用法。更关键的是 textarea 的 `onKeyDown` 只处理 Enter 发送 —— **弹窗开着时按 Enter 会把消息直接发出去**，
而不是选中成员。

### 2. `.md-body a` 根本没有样式，裸外链走了浏览器默认色

`styles.css` 是唯一的样式文件（纯 CSS 变量方案，无 Tailwind）。全文件检索 `a {` / `a:link` / `.md-body a`
**零命中**，所以 `<a>` 继承 Chromium 的 `-webkit-link` 暗蓝 `#0000EE`；在暗色气泡
（`--bubble-ai: #2c2c2c`）上对比度极低。系统里其实已有「暗色用亮蓝」的先例，但只作用于站内文件链接
`.md-file-link`（硬编码 `#7fa7ff`），普通超链接没被覆盖。

### 3. 会话默认名是硬编码的展示文案，且私聊标题由引擎持有

* 群「会话记录」的默认名来自 [`groupThreads.ts`](../../../packages/core/src/orchestrator/groupThreads.ts) 的
  `defaultTitle()`，写死为 `会话 · M/D HH:mm`，不存在任何"任务名"概念。
* 私聊会话（「聊天记录」抽屉）标题由 opencode session 持有，建会话时写死 `与 {agent} 的聊天`。
* 全仓库**没有任何**从首条用户消息生成标题的逻辑。

## 三、方案与关键决策

经 grilling 逐项确认：

| 决策点 | 结论 |
|---|---|
| 「任务中文名称」来源 | 截取首条用户消息（不调模型，零成本、离线可用） |
| 作用范围 | 群「会话记录」+ 私聊「聊天记录」都改 |
| 旧会话 | **只对新会话生效，不回溯**（旧 meta 无标记字段，天然不动） |
| 收尾 | bump PATCH + 双平台打包 + 推代码，不打 tag / 不发 Release |

**私聊为什么不另建一套 Jeff 侧名字表**：会话名只作为界面显示名，直接写进 opencode 的 session title
（即现有 `renameSession` 已经在用的那条 `oc.updateSession` 路径）最省事。原方案曾担心
`listAgentSessions` 靠 `s.title.startsWith('与 X 的聊天')` 过滤会因改名而漏会话，实测 opencode 的
`session` 表**持久化了 `agent` 字段**（`.jeff/oc-home/data/opencode/opencode.db` 中实测
`"agent":"jeff_xiaojie"`，与 `agentSlug()` 输出一致），而过滤条件是
`s.agent === slug || 上述前缀`，`agent` 分支恒命中 —— 改标题不会漏会话，因此**不需要**改动
`listAgentSessions`，也不需要引入 `sesmeta` 旁路映射。

## 四、改动清单

### 1. `@` 提及键盘选择

  * 新增 `mentionIndex` 状态；候选集（`mention.query` / 候选数）变化时重置为 0，防止索引指向已消失的成员。

  * `pickMention` 的替换范围由"读实时光标位置"改为 `mention.start + 1 + mention.query.length`
    这一确定区间（键盘导航后光标未必还在查询串末尾，用实时位置会插错地方）；插入后把光标用
    `setSelectionRange` 落在 `@成员 ` 之后，继续输入不用手动挪。
  * 候选项带 `active` class、`onMouseEnter` 同步高亮、`data-testid` 便于测试。

  `.mention-item.active` 合并为同一条规则，鼠标与键盘高亮视觉一致。

### 2. 暗色链接亮蓝

* 亮色变量块新增 `--link: #2563eb`，暗色块新增 `--link: #7fa7ff`（与既有文件链接暗色值统一）。
* 新增缺失的 `.md-body a` 规则（`color: var(--link)` + 下划线 hover）；因为颜色走变量，一条规则同时覆盖亮/暗，
  不再需要重复的暗色覆盖块。
* `.md-file-link` 里硬编码的 `#2563eb`/`#7fa7ff` 换回 `var(--link)`，顺带修正其违反文件头
  「组件只吃变量，禁止硬编码色值」契约的问题。

### 3. 会话默认命名

新增 [`packages/core/src/util/title.ts`](../../../packages/core/src/util/title.ts)：

* `stampTitle(date)` → `20260911-1430`
* `placeholderTitle(createdAt)` → `20260911-1430-新会话`
* `summarizeTaskName(text, max=16)` → 去代码块/图片/链接目标/`@某某` 提及，压平空白，去尾部标点，
  按**码点**截断（不切断中文/emoji，超长补 `…`），空结果（如只发图片）回落 `新会话`
* `composeAutoTitle(createdAt, text)` → `{创建时间戳}-{任务名}`

群会话（`groupThreads.ts`）：`GroupThreadMeta` 增加可选 `autoTitle`；`createThread` 无显式标题时用占位名并置
`autoTitle=true`；新增 `autoTitleFromFirstMessage()` 在首条用户消息落库后补任务名并置 false；
`rename()` 置 false；两处 `'默认会话'` 兜底改走新模板。`ensureMigrated` 的**旧数据迁移分支保持
「默认会话」**，不用"当下时间"改写历史会话的名字。

钩子位置在 [`group.ts`](../../../packages/core/src/orchestrator/group.ts) 用户消息落库 + `touch()` 之后、
`runTurn` 之前 —— 这样该回合新建的 agent 会话标题（`${thread.title} · ${agent.name}`）也能拿到补好的名字。

私聊（`private.ts`）：建会话标题改为占位名，并把创建时刻写入 KV `sesauto:{sessionId}`（同时充当
"还没补名"标记位）；`doSend` 在停止判定之后、`sendMessage` 之前调 `maybeAutoTitle()` —— 改名失败
**只记 `private-autotitle-fail` 日志并保留标记下条重试，绝不打断用户发送**。

# 私聊聊天记录并入「资料」抽屉 + 顶栏操作图标化（v1.7.23，同一会话后续迭代）

> 仓库版本：1.7.22 → **1.7.23**（PATCH：把已有能力换个入口 + 视觉统一，无破坏性变更、无独立新能力）

## 一、用户报告

1. 私聊的历史记录没有和群聊统一，应改成与群聊一致的交互。
2. 「压缩、新会话、资料」这些操作应换成图标（不是 emoji）。
3. 提交代码并重新编译双平台。

## 二、根因：两个历史记录的实现是两份代码

* 群聊：`GroupInfoDrawer` 的「会话记录」Tab（在「群资料」抽屉里），列表行内提供 改名 / 继续 / 删除，顶部有「+ 新会话」。
* 私聊：顶栏一个时钟图标打开的**独立抽屉** `ChatHistoryDrawer`，行内只有「改名」，「继续 / 删除」藏在右侧预览底部，也没有「新会话」入口。

两者虽然当时共用 `.history-item` / `.history-preview` 等 CSS 类，但 JSX 与交互是各写一份 —— 这就是「不统一」的根源，也意味着以后很容易再次漂移。

另外顶栏的「压缩 / 新会话 / 资料（群资料）」都是 `text-btn` 文本按钮，只有「聊天记录」是 SVG 图标，同一排里图标与文字混用。

## 三、方案与关键决策

* **私聊历史并入「资料」抽屉当一个 Tab**（用户选择）：顺序与群侧对齐为 基本资料 / 模型设置 / **聊天记录** / 工作区文件，群是「群资料 → 会话记录」，私聊就是「资料 → 聊天记录」，两边结构完全对称；顶栏那个独立的时钟图标随之去掉。
* **抽出共用组件而不是再写一份**：新增 `SessionHistoryPanel`，群侧与私聊侧都渲染它。面板自己持有 `items / preview / 编辑态 / error` 状态，调用方只提供 6 个 IPC 适配回调（`loadItems / loadPreview / rename / activate / remove / createNew`）+ 文案与 testid。这样**「统一」是被结构保证的，而不是靠人肉同步两份 JSX**。
  * `activate`（继续）与 `createNew`（新会话）由调用方决定是否顺带关抽屉 —— 群与私聊都是关掉抽屉回到聊天主窗，与改造前的行为一致。
  * 群侧原有的「消息条数」（`· N 条`）保留：`SessionHistoryItem.messageCount` 可选，私聊不传就不渲染。
  * 群侧原有 testid 全部保留（`group-chat-history` / `group-new-thread` / `thread-title-<id>`），E2E 不受影响；另补齐了通用的 `session-rename-<id>` / `session-activate-<id>` / `session-delete-<id>`，两侧都能用同一套选择器。
  * 群侧原来把预览消息渲染成 `m.sender_name || '对方'`，面板沿用同一规则。
* **图标不用 emoji**：新增 `components/ui/Icons.tsx`，导出 `IconCompress / IconNewSession / IconProfile / IconGroupProfile / IconClose`（24×24 viewBox、`stroke="currentColor"`，因此自动跟随主题变量）。emoji 的字形与配色由系统字体决定，跨平台长得不一样、颜色也不跟主题走，这正是要换掉它的原因。
* **压缩按钮的「进行中」反馈**：原来靠按钮文案「压缩中…」表达，改图标后文案没了。用 `.icon-btn.is-busy svg` 加 1s 呼吸动画（`@keyframes icon-pulse`）+ `disabled` 兜住反馈，`title` 同步改成「压缩中…」。
* 顺带补齐 `.icon-btn:disabled` / `.text-btn:disabled` 的置灰样式（原来 `:disabled` 只有 send-btn / btn.primary / plus-menu-item 有样式，禁用态看不出来）。
* 私聊「资料」抽屉宽度**保持 720px 不变**：两栏面板最低需要约 512px，720px 下能完整展开；加宽会改变已按 720px 设计的智能体表单观感，不属于本次诉求。
