# 双机自动部署与真机验收

日期：2026-10-07

## 目标与流程

入口为 `npm run deploy:windows -- --target win11 --android auto --suite <测试集>`。命令必须指定 `deploy/suites/` 中的具名测试集；先完成 Ubuntu 本地回归，构建 Linux/Windows 桌面安装包及签名 Android release/test APK，在 Ubuntu 的 `jeff` AVD 安装本次 APK 并运行 instrumentation。AVD 通过后，Windows 端按 USB serial、`192.168.3.121:5555` 的顺序选设备；自动模式下没有真机时保留模拟器通过、真机待验收的状态。

上传前生成包含版本、提交号、文件大小与 SHA-256 的清单。Windows worker 再次核验哈希后，通过独立提权任务静默安装同范围的 NSIS 包，启动已安装的 Jeff 并使用隔离 home / Electron 数据目录运行具名桌面断言。证据保存在 `.tmp/deploy/<运行编号>/`。

Windows 真机在 instrumentation 中明确断连时，Windows worker 保存设备状态和错误，Ubuntu 重跑整套 AVD instrumentation；签名、安装或仍在线设备上的功能断言失败不会被降级为成功。

## 首次配置

Windows 初始化脚本位于 `deploy/windows/Configure-Windows.ps1`，详细步骤见 `deploy/windows/README.md`。它配置限定 Ubuntu 来源 IP 的 SSH 防火墙规则、公钥认证、登录用户桌面验收 worker 及独立提权安装任务。Ubuntu 的主机别名与运行配置放 `.tmp/deploy/`，不入库。

### Android：AVD 通过，192.168.3.121 设备功能验收失败

- Ubuntu `jeff` AVD 安装同一签名 release APK 与匹配签名测试 APK，三项 instrumentation 通过：WebView 正文、横屏视口填满、联系人/个人页导航。移动端 12 项单测和 21 项 E2E 通过。
- Windows 无 USB 设备；使用 SDK ADB `D:\soft\android\sdk\platform-tools\adb.exe`，显式指定 `-s 192.168.3.121:5555` 完成 APK/test APK 安装、版本核对、instrumentation、日志与截图回传。
- 网络设备为 RK3288、Android `8.1.0`，系统 WebView `61.0.3163.98`。安装版本 `1.11.5` / `11105` 正确，但 instrumentation 未通过，报告 `passed: false`；没有将 ADB 或 SSH 的退出码当作验收成功。
- 为排查白屏加入 legacy JS/polyfills 与旧 WebView 的 vh/env CSS 后，AVD 回归仍通过；该设备仍白屏。通过 Windows ADB 转发其 WebView CDP，在实际 release APK 中确认 legacy bundle 的 `nonceFor` BigInt 字面量处出现 `SyntaxError: Invalid or unexpected token`。旧 WebView 不支持 BigInt，而 Babel legacy 转换不能补齐该能力；因此该兼容尝试尚不能支持 WebView 61。
- 旋转测试同时触发设备 `com.android.settings` 的 ActionBar 异常与“设置已停止运行”遮罩，属于独立的设备系统异常；未将其误记为 Jeff 原生崩溃。原始失败与复测证据分别保留在 `android-first-attempt/` 与 `windows-evidence/`，解析证据为 `android-cdp-diagnosis.json`。
- 结论为“模拟器通过，指定网络设备安装成功但功能验收失败”，不能表述成真机通过或自动降级掩盖失败。

可以。实测已从 Ubuntu 完成 Windows 文件传输、静默升级、交互桌面实际安装版界面操作与截图，并调用 Windows ADB 在网络 Android 设备安装、测试和取证；这条链路不依赖 Windows Codex。Windows 图形验收需要已登录的交互用户会话，普通 SSH 会话不应直接承担桌面 UI 测试。

## Android 兼容修复与最终交付（1.11.6）

本轮两个目标均以真实环境验证：已将 Ubuntu → OpenSSH/SFTP → Windows 交互计划任务/CDP → Windows SDK ADB 的方式写入 `AGENTS.md`，明确默认不使用 Windows Codex；修复了 RK3288 / Android 8.1 / WebView 61 的启动与消息展示兼容问题。此前 1.11.5 和中间 APK 的失败记录作为历史保留，以下为最终结果。

### 两处根因与修复

1. **BigInt**：legacy JS 转换无法转换加密依赖的 BigInt。共享协议新增原语模块边界；桌面/relay 保留 noble 实现，移动端构建替换为 TweetNaCl 的 Ed25519/X25519 与 StableLib 的 AES-256-GCM、HKDF-SHA256。协议标签、握手材料、密钥格式、AAD 和消息序号保持一致，不关闭加密，不改变已有绑定数据。nonce 用安全整数分字节编码，拒绝不安全计数器，避免精度造成 nonce 重用。
2. **消息展示白屏**：真实消息使 GFM 邮箱自动链接解析触发旧 WebView 不支持的后行断言。移动端构建将其改为捕获边界字符并原样保留，同时保留上游 URL/域名校验；没有移除 Markdown、邮箱、链接或表格功能。对照上游的邮箱边界、中文标点、连续邮箱、路径及 URL 行为进行回归。

另将 APK versionName / versionCode 从 mobile/package.json 自动派生，防止 renderer、仓库和 APK 元数据漂移。本轮统一 PATCH 为 `1.11.6` / Android versionCode `11106`。

采用库与兼容背景参考：[TweetNaCl.js](https://github.com/dchest/tweetnacl-js)、[StableLib GCM](https://www.stablelib.com/classes/_stablelib_gcm.GCM.html)、[Babel BigInt 说明](https://babel.dev/docs/babel-plugin-syntax-bigint)、[GFM 自动链接实现](https://github.com/syntax-tree/mdast-util-gfm-autolink-literal)。
