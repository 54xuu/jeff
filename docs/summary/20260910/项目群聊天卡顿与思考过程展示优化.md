# 项目群聊天卡顿、思考过程小窗展示与 Markdown 预览器关闭方式（v1.7.18）

## 问题

用户在「POCT+AI 项目管理」项目群使用中提出三点：

1. **流式输出中途卡住（像软件死了）**：发消息开始正常，过一段时间后界面卡住；但其它 Tab 还能点，切出去再切回这个群，就能看到输出正确、完整的回复。
2. **思考内容混在流式输出里不断刷**：感觉刷出来的其实是思考内容；希望这部分固定在一个小范围里显示，并且可以展开查看。
3. **Markdown 预览模态框容易被误关**：点旁边空白处就会关掉，希望只能点 `✕` 才关。

## 根因（读代码 + 实测定位）

### 1. 卡顿的真凶：**流式过程中每个 token 都重跑一遍 mermaid 渲染**

`MermaidBlock.tsx` 的 `useEffect` 依赖 `[code]`，**没有任何防抖**——正文里只要出现 ` ```mermaid ` 代码块，流式期间每个增量都会触发一次完整的 `mermaid.render()`：图表源码此时还不完整，mermaid 既解析报错又重新布局（mermaid + cytoscape 上 MB 的解析/排版都在主线程），直接把主线程堵死。这解释了「过一段时间才卡」（模型开始画图的那一刻）和「切走再切回就好」（完成后只渲染一次）。

叠加另外三处放大因素：

- **无节流**：SSE 每个 delta 直接 `emitStream` → IPC 广播 → 写 Zustand store → React 重渲染；
- **每条增量都全量重解析 Markdown**：`rehype-highlight` 对整篇累计文本重新做语法高亮；
- **强制同步重排**：每次 token 都 `el.scrollTop = el.scrollHeight`，触发 layout thrashing。

「切走再切回就正常」的原因：切走时组件卸载，后台继续生成并落库；切回时组件挂载，从 SQLite 一次性渲染最终消息，不再有高频重渲染。

### 2. 思考内容的两种来源

- 原生 reasoning（`field: 'reasoning'` / `part.type === 'reasoning'`）：已有折叠区，但**默认收起**且展开后无高度限制；
- 部分模型（DeepSeek-R1 等第三方兼容网关）把思考直接写在正文的 `<think>…</think>` 里：项目里**完全没有解析**，于是大段推导直接糊在正文气泡里。

### 3. 预览器

`MarkdownPreviewModal.tsx` 的 `.preview-mask` 上绑定了 `onClick={close}`，点遮罩即关。

## 方案（grill-me 逐问确认的口径）

- 思考内容**双重兼容**（原生 reasoning + `<think>` 标签），**思考中**自动展开成限高小窗（窗内跟随滚动），**开始出正文即自动收起**，点击可随时展开复盘（展开后也限高）；历史消息同享同一套剥离与折叠逻辑。
- 卡顿走**分层治本**：前端批量节流 + 流式阶段轻量渲染（重量级渲染延后到输出完成）+ 滚动防抖。
- 预览器只保留 `✕` / `Esc` 关闭，遮罩点击不再关闭。

## 实现

### 新增：`<think>` 提取工具（packages/core/src/util/thinkTag.ts）

纯函数、无 Node 依赖，从 `browser.ts`（渲染进程安全入口）与 `index.ts` 同时导出：

- `extractThinkTags(md)` → `{ text, reasoning[] }`：抽取 `<think>` / `<thinking>`（大小写不敏感），**兼容流式未闭合标签**（已收到的推导归入思考、正文不显示半截内容），**围栏代码块内的 `<think>` 原样保留**（那是文档内容），剥完自动清掉正文里的空行残留；
- `mergeReasoning(native, fromText)`：把原生 reasoning 与标签提取结果合并成折叠区用的列表。

单测 `packages/core/tests/thinkTag.test.ts`（9 例）覆盖闭合/未闭合/多块/同行混排/代码块豁免/空块。

### 流式轻量渲染（Markdown.tsx）

新增 `live?: boolean`：

- `live` 时不挂 `rehype-highlight`（每个 token 对全文重做语法高亮是纯烧 CPU），输出完成转历史消息渲染时一次性高亮到位；
- `live` 时 **mermaid 代码块按普通代码块展示**，不调 `mermaid.render`；输出完成后再出图。

### 自适应批量节流（store.ts）

`chat-stream` 不再逐条写 store，先进缓冲区、到点一次性写入；**合并窗口随文本长度放宽**（<3KB 40ms / <10KB 80ms / <24KB 130ms / 更大 200ms），因为每次刷新都要把整篇文本重新解析成 Markdown，只有拉长间隔才能把每秒渲染占用压成常量级。有数据待写时不重置计时器，避免长文档持续输出被无限推迟；`done` / `chat-updated` / `group-updated` 会丢弃对应 key 的待写增量，防止旧数据把已清空的流写回来。

### 滚动防抖（ChatShared.tsx `useAutoScroll`）

抽出共用 hook：`requestAnimationFrame` 合并滚动写入，并加**贴底判断**（距底 <80px 才自动跟随）——用户在往上翻历史时不再被强行拽回底部。

### 思考小窗（ChatShared.tsx `AssistantExtras` + styles.css）

- `live && !bodyStarted` 判定为「思考中」：自动展开，`.extra-reasoning.thinking` 限高 140px、窗内跟随滚动，标题栏显示绿色「思考中…」；
- 开始出正文：自动收起为「思考过程」；用户手动开合会被记住（`onToggle` 只记录与渲染值不一致的变化，避免 React 自己改 `open` 时误判）；
- 手动展开后限高 320px 带内滚动，长篇推导不会撑爆聊天窗。

三处气泡（流式 `StreamingBubble`、私聊历史 `MessageBubble`、群聊历史 `GroupBubble`）统一走提取逻辑，复制按钮也复制剥离后的正文。

### 预览器关闭方式（MarkdownPreviewModal.tsx）

移除 `.preview-mask` 的 `onClick={close}`（连带 panel 的 `stopPropagation` 也一并去掉），只保留 `✕` 与 `Esc`。

### 顺带修复

仓库里 `packages/core/src/version.ts` 的 `APP_VERSION` 还停在 `1.7.16`（上次发版漏改），导致 `npm test` 的版本一致性用例一直红；本次统一到 `1.7.18`。

`apps/desktop/e2e/ui.spec.ts` 里「群资料」断言仍是上一版单页抽屉的写法，未点「会话记录」Tab 就断言会话记录可见——上次「资料 Tabs 重构」后就成了陈旧用例（改动前后一样失败），已按新 Tab 结构修正。

## 遗留观察（本次未改，供后续决策）

1. **core 每条增量重发整篇文本**：`emitStream` 每次广播都带完整累计 `text`，IPC 载荷随回答变长而线性增长（1200 tok/s 级的人工洪泛下这部分开销会盖过渲染开销）。若后续还有长回答卡顿，可考虑在 core 侧按 ~60ms 合流，或改成只发增量。
2. **群内成员交接会重拉上下文预览**：`GroupWindow` 的 `ctxPreview` effect 依赖 `ctxAgentId`，多成员接力的回合里每次交接都会走一次 `contextPreview`（内部 `oc.getMessages()` 拉整段会话再分词）。本次未实测其耗时，若群协作长回合仍卡，这是下一个怀疑对象。

# 追加：思考过程/工具调用改为「恒一行折叠条」+ 工具调用落库丢失修复（未发版）

同一天用户继续反馈上一版（v1.7.18）的思考小窗仍不满意，提出三点：

1. 在项目群里提问，**所有群成员的处理过程都会不断流式输出很长**（怀疑是思考内容），但**任务完成后这部分内容又不见了**；
2. 思考内容、工具调用这类「不属于回答」的部分，应该**用特定样式在一行显示，只有用户主动点击才展开**；
3. 流式过程中也要**固定一个区域**流式输出（对齐 ZCode 的「一行显示」）。

## 根因

### 1. 「不断输出很长」= v1.7.18 的思考小窗**只在思考阶段自动展开**

`ChatShared.tsx` 里 `thinking = live && !bodyStarted`，成立时 `autoOpen = thinking` → 折叠区被**强制展开**成 140px 小窗。推理模型（DeepSeek-R1 等）一次能吐几千字思维链，展开的小窗就在那里持续刷屏——这正是用户看到的「不断流式输出很长」。

### 2. 「完成后不见了」是**两个原因叠加**

- **表层**：正文一开始（或回合结束）`thinking` 变 false → 自动收起为不显眼的折叠条；同时 `<think>` 被从正文剥离，视觉上「那么大一段突然没了」。内容其实还在折叠条里，但用户完全不会去点。
- **深层（真丢数据）**：**工具调用在落库时整段丢失**。opencode 一轮对话里「模型 → 工具 → 模型」的每次往返都会新建一条 assistant 消息，`OcClient.sendMessage` 只返回**最后一条**（纯文本那条）的 `parts`；`group.ts` 的 `runTurn` 从 `reply.parts` 里筛 `tool` part 写进历史消息 meta，于是**前一条 assistant 消息上的 tool part 永远拿不到**。表现就是：流式期间能看到「工具调用 1 / 运行中… bash」，落库进历史后工具条完全消失。（同理，工具调用前那段 reasoning 也会丢。）

## 方案（grill-me 逐问确认）

- 思考过程、工具调用**都改成「恒一行折叠条」**：默认一律收起，只有用户点击才展开；展开后仍限高 320px 带内滚动。
- 流式期间在这**同一行内**做实时预览：思考显示「思考中…」+ 最新一行推导（单行 ellipsis 截断），工具显示「运行中…」+ 当前工具名；长文本永远不换行、不撑版面。
- 正文开始后实时预览与「思考中…」徽标消失，折叠条转为静止态，正文照常流式输出。

## 实现

### 前端：`AssistantExtras` 去掉自动展开（ChatShared.tsx）

- 删掉 `autoOpen`/`userOpen` 双状态，改为单一 `reasonOpen = useState(false)`，`<details open={reasonOpen} onToggle={e => setReasonOpen(e.currentTarget.open)}>`；`open` 由状态单向控制，同值 setState 自动 bail out，不会与 React 自身的 open 变更打架。
- 新增 `tailPreview(text, max=140)`：取思考文本**最后一个非空行**，超长则截末尾 140 字符并前缀 `…`（要的是「最新」而不是「开头」）。
- 摘要行结构：`思考过程` +（思考中）`思考中…` + `<span class="extra-preview">{最新片段}</span>`；工具条：`工具调用 N` +（执行中）`运行中…` + 工具名。
- 顺手把标签包进 `.extra-label`，避免 flex 布局里裸文本节点被压缩换行。

### 样式：单行硬约束（styles.css）

- `.msg-extra > summary` 加 `min-width: 0; white-space: nowrap;`；
- `.extra-label` / `.extra-live` 用 `flex: 0 0 auto`（不被压缩）；
- 新增 `.extra-preview { flex: 1 1 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }`——预览独占剩余宽度并省略；
- `.extra-live` 加呼吸小圆点（`::before` + `@keyframes extra-live-pulse`）作为「还在跑」的统一视觉信号。

### core：补齐本轮所有 assistant 消息的 reasoning/tool part（oc/client.ts）

新增私有方法 `mergeTurnParts(last, msgs)`，在轮询到 `time.completed` 后、返回之前调用：

- 用 `last.parentID`（= 触发本轮的 user 消息 id，opencode `SessionPrompt.runLoop` 对每条 assistant 都这么设）定位本轮起点，取 `(user 消息, 最后一条)` 之间的 assistant 消息；
- 只合并它们的 `reasoning` / `tool` part，**放在 `last.parts` 之前**（保持时间顺序）；
- **`text` part 完全不动**——调用方（`group.ts` 的 `content`、`delegate.ts`、私聊）对「回复正文」的判定与 @提及解析行为不变，避免影响流水线路由。

- 群聊里「思考过程」+「工具调用」现在是**两条独立的单行折叠条**（共两行）。若希望进一步压成一行（如 `思考过程 · 工具调用 1`），需要把两类信息合并进同一个折叠容器，属于另一次交互决策。
- 若一轮里工具被调用多次，`工具调用 N` 只体现条数；流式期间的单行预览只展示**当前运行中**的那个工具。
