# 内置浏览器：分辨率控制（4:3 / 精确像素）+ 整页截图（智能体分析网页并落盘）

## 命题

用户任务：**智能体通过内置浏览器分析网站内容并把截图保存到本地**，四个分步骤目标：

1. 打开 `https://mp.weixin.qq.com/s/HRJc3icbpxntCyJ9Qwg2Rw`，分析内容并总结保存为 `{网页标题}.md`（含「原文、总结」两部分）；
2. 控制浏览器分辨率在 **4:3**（中途追加：还要支持**自定义分辨率**，如 `1697x1063`）；
3. 截图保存到本地目录，**必须包含网页全部内容（含滚动的部分）**；
4. 界面符合整体交互与样式规范；
5. git add & commit & push，只推代码与文档，**不打 tag、不发 release**。

动手前经三路探索摸清链路，三个设计决策由用户确认：**4:3 = 比例自适应**（按面板算最大 4:3 盒居中留白）、
**自定义分辨率 = 精确像素渲染**（严格等于请求值，超出面板时面板内滚动而不缩放）、**验收 = 封闭 E2E + 真模型实测**。

## 一、分辨率控制（人机同一份设置）

- 工具栏新增显示器图标 → 菜单：**自适应（铺满面板）/ 4:3 比例（随面板自适应）/ 自定义分辨率**（`1697x1063` 回车生效，非法值给提示且不生效）。
- 智能体侧新增 `jeff_browser_set_viewport`：`preset="4:3"` / `preset="auto"` / `width`+`height`，**与界面菜单改的是同一份 state**（store + localStorage `jeff-browser-resolution`，本机偏好、不参与跨设备同步）。改完界面图标点亮，人和 agent 看到的是同一个页面尺寸。
- 实现：webview 元素没有 viewport 属性，**页面视口就是元素的盒尺寸**——所以直接改内联宽高（`flex:none` 必须显式写，否则 1697px 的盒会被窄面板压扁，视口就不是请求值了）。比例模式容器 `overflow:hidden`（避免滚动条与可用宽度互相追赶），精确像素模式 `overflow:auto`（面板内滚动查看）。
- 分层模型与三栏宽度同源：store 里存**请求值**，渲染时按面板容器算出**生效尺寸**（4:3 随面板重算），生效尺寸才是页面视口/截图/工具返回值的来源。面板重开（webview 重建）后由创建处补一次应用，否则分辨率会丢。

## 二、整页截图：三条路，前两条都是死路（实测数据）

| 走法 | 实测结果 | 结论 |
|------|----------|------|
| 把 webview 元素撑到整页高再 `capturePage()` | 请求 541x5659，拿回 **1082x1946**（=541x973 @2x）；元素撑多高都不多栅格化 | ❌ 拉伸那张图 = 一张**空白图**（第一版就这么假绿过：断言只看尺寸） |
| 滚动页面再 `capturePage()` 当前视口 | 每片都只有滚动条、**内容为空**（滚动区域不会重新光栅化）；等 500ms、`fromSurface:false` 都无效 | ❌ |
| **CDP 按文档坐标分片 + canvas 拼接** | 每片 `Page.captureScreenshot({clip:{y:文档偏移}, captureBeyondViewport:true, scale:1})` = 视口宽×视口高，拼接后首中尾都有内容 | ✅ |

- 主进程新增 `IPC.browserPageShot`（`webContents.fromId(guest)` → `debugger.attach('1.3')` → 截图 → detach）。
- **高 DPI**：CDP 按**设备像素**出图（541x406 → 1082x812），按整数倍因子用 `nativeImage.resize` 压回请求的 CSS 像素 → 「设了什么分辨率就拿到什么尺寸的图」跨 DPR 成立，断言才立得住。
- **懒加载**：整页前先滚一遍页面引出 `data-src` 图片，再 poll `document.images` 的 pending/未触发计数（微信/少数派这类长文不这样做，图会是一片空白）。
- **固定顶栏**：第二片起把 `position: fixed/sticky` 元素临时 `visibility:hidden`（首片保留），截完还原——否则每片都会重复拍到顶栏。
- 契约（写进 `docs/built-in-browser.md`）：视口截图**精确等于当前视口**（CSS 像素）；整页 = 内容宽 × 文档高，cap 16384px，超出 `truncated:true`；返回值 `width/height` 就是落盘 PNG 的真实尺寸。

## 三、硬边界：截图范围不能超过 Jeff 窗口（如实拒绝，不给歪图）

实测渲染表面大约只覆盖到**窗口尺寸出头一点**：窗口 1290x748 时，请求 1697x1063 拿回的图尺寸对、内容却整体错位（红带丢失）；
请求 5659 高的整页会平铺成「页首内容重复」的假图。1600x900（小于窗口）则完全正确。

因此渲染层在截图前做**窗口尺寸校验**：`width/height` 超出 Jeff 窗口就明确报错，并提示「把窗口放大（或拉宽面板）或把分辨率改小」。
面板比窗口小没关系（面板内滚动即可），窗口本身必须装得下——这比产出一张「看着像、其实不全」的图诚实。

## 四、验收

### 封闭 E2E（进仓库回归，`apps/desktop/e2e/v18.spec.ts` 的 v1.8.7 组）

判据落在**页面自报的事实**与**落盘 PNG 的真实像素**上，不是 DOM 样式：

- 4:3：页面自己报的 `innerWidth x innerHeight` == 工具返回的生效尺寸，比例误差 <0.01；
- 自定义：`1280x720` 下页面自报严格 `1280x720`；视口截图 PNG == `1280x720` 且**顶部有内容**；
- 超窗口分辨率：页面视口照样精确生效（布局不受窗口限制），但截图**必须失败**且报错含「超过 Jeff 窗口」；
- 整页：测试页造 5200px 高 + 三张 800ms 懒加载图 → PNG 高 ≈ 文档高、**像素级首尾色带都在**（红带在顶、蓝带在底）、懒加载图 3/3 加载完成；
- 超长页（20000px）：`truncated:true` 且高 = 16384；
- 参数边界：只给一边 / 越界 / 不认识的 preset → 明确报错；**全字段空串 → 报错（不静默改回自适应）**——模型一次「全字段补空」的 update 不能把已设好的分辨率抹掉；
- 界面：菜单切 4:3 / 输入自定义 / 非法值提示、localStorage 落值、**面板关闭重开后偏好不丢**。

## 五、参数硬规矩（回归用单测钉住）

`tools/browserArgs.ts` + `tests/browser-args.test.ts`：

- 参数**只用平铺标量**（`preset` / `width` / `height`），嵌套对象一律会被模型丢成空串；
- `width/height/preset` 的**空串 / 未传一律当「未提供」**，三个字段全空则**明确报错**（`没有要设置的分辨率`），而不是静默改回自适应；
- 容错：`4：3`（全角冒号）、`"1697px"`、字符串/数字混传都认；越界/只给一边/不认识的 preset → 可读报错；
- 工具返回值形状写进描述，模型知道「生效的分辨率」与 `truncated`。
