# 第二项任务：WebDAV skills 整目录镜像备份/恢复（v1.7.25）

## 需求规则

1. 「备份」= 全量备份上传：远端 `skills/` 与本地 `~/.agents/skills` **整目录镜像对齐**；
2. 「从备份恢复」= 直接把 skill **整个目录替换**为备份内容；
3. 目标：用户只维护 `~/.agents/skills` 一份目录，多平台通用；
4. 适配 Windows 与 Linux；5. 测试通过后重编译双平台并提交。

## 实现（`packages/core/src/sync/engine.ts`）

- **backupSkills 改镜像语义**：新增/变化文件上传（hash 跳过不变）；备份末尾 `listRemoteFiles` 对账，**远端有、本地没有的文件 → 旧版先归档到 `skills-versions/` 再从远端 DELETE**（本地删除操作传播到其他平台）。本地 skills 目录不存在时报错跳过，**不把远端清空**（新机器保护）。`hashes` kv 同步增删，报告新增 `deleted` 计数。
- **restoreSkillsApply 改整目录替换**：先把本地现状全量快照到 `<data>/backups/skills-<时间戳>/`（可手工回退），然后 `rm` 本地 skills 目录全部内容、把暂存区文件原样拷回。恢复完成后用恢复内容重建 `hashes`（下次备份不会无谓全量重传）。报告新增 `removed`（被移除的本地多余文件数）。
- **跨平台**：远端相对路径统一 posix（`/`）；`listSkillFiles` 上传时 `path.sep → '/'`、恢复时按 `/` 拆分用 `path.join` 落盘，Windows 备份的内容 Linux 直接恢复（新增单测覆盖子目录场景）。
- **UI**：`SyncSettings` 文案改为镜像/替换语义，恢复确认弹窗明示「备份里没有的本地文件会被删除」，报告行增加「远端删除 N」；内置说明（小杰使用说明）同步更新。

## 测试（三层）

1. **单测**（`tests/skills-sync.test.ts` 重写为镜像语义，4 例全过）：全量上传/未变跳过/镜像删除（删前归档）/本地目录缺失不清空远端/整目录替换（removed 计数、快照回退、恢复后备份零重传）/posix 子目录跨平台/并发重入锁。**开发中抓到一个真 bug**：镜像删除循环漏了 `report.archived += 1`（归档成功但计数为 0），靠断言抓出。
2. **真实 WebDAV 联测**（新增 `tests/skills-sync.live.test.ts`，`SKILLS_LIVE_E2E=1` 门控；用真实 WebDAV、独立 basePath `/jeff-skills-selftest-<ts>` 沙箱，测完自动清理，**不触碰真实 `/jeff` 数据**）：模拟平台 A（win）/平台 B（linux）闭环——A 备份 → B 整目录恢复（老文件被移除）→ A 删/改/增后备份 → B 恢复（删除传播、多余移除、修改生效）→ B 恢复后立即备份零上传零删除。**1 例通过（20s）**。踩坑：该 webdav 库无 `deleteDirectory`，且远端删目录必须带尾斜杠 `deleteFile(`${BASE}/`)`。
3. **快速回归**：core 全量单测 185 passed；typecheck 仅存量 3 个 e2e helper 报错；mock UI E2E 通过。

# 第三项任务：skills 备份/恢复真实使用问题修复（v1.7.26）

## 用户实测反馈（Windows + Ubuntu）

1. Windows 点「备份」后「备份中…」卡约 5 分钟才有反应；
2. Ubuntu 点「从备份恢复」后「检查中…」约 5 分钟才出结论；确认恢复后 `~/.agents/skills` 全空。

## 根因定位（真实 WebDAV 服务器实测）

- **慢**：备份/恢复对每个文件**串行**发请求（Ubuntu 本机 531 个文件、约 85 个目录），单请求 ~280ms；且每文件还要 ensureCollection（2~3 个请求）。**更关键**：v1.7.25 的 stage 下载部分请求**没有超时信号**，服务端偶发把请求静默挂起（长连接复用被网关断开），Node undici 默认 300 秒才放弃——正好是用户看到的「5 分钟」。
- **目录空**：用户的 Windows 机器上 `~/.agents/skills` 内容不全（或为空），镜像备份把它同步成远端状态；Ubuntu「从备份恢复」= 整目录替换 → 本地被换成 Windows 的残缺内容。**旧版缺两道保护**：①本地目录为空/残缺也照常镜像清空远端；②远端备份下载不全时仍允许整目录替换。
- **服务端坏条目**：真实服务器上存在 20 个「父列表标为目录、但 PROPFIND 405 / GET 401 / DELETE 401」的僵尸条目（html-ppt 旧版本遗留 + node_modules 子目录），会把恢复的目录列举卡死。

## 修复（`packages/core/src/sync/engine.ts`）

1. **并发化**：新增 `pMap`（并发 8）——上传、镜像删除、stage 下载全部并发；目录创建缓存（同目录只探测一次）。
2. **每个请求独立超时**（`AbortSignal.timeout`，不再共享一个总信号——共享信号会让第一个挂起请求吃光预算、重试立即被杀）；GET/列目录带**失败重试一次**（`davGetWithRetry`/`davListWithRetry`，中止会销毁坏连接，重试走新连接即恢复）；`ensureCollection`/`collectionExists` 内部请求也补超时。
3. **stage 严格列表**：目录列举失败时——401/405 类确定性坏条目 → 跳过并记入 `warnings`（设置页黄字提示手工清理）；其他错误（超时/5xx）→ 中止，**绝不用不完整列表做恢复**；单个文件下载失败 → 中止并报告，本地未改动。
4. **备份安全阀**：本地目录不存在、或**本地为空而远端有备份** → 报错跳过，不改动远端（防错误路径/空目录把远端清空）。
5. **恢复安全阀**：远端没有任何备份文件 → stage 直接失败，UI 不出现「确认恢复」；apply 改为「先备好再换入」——暂存区先完整拷到 ready 目录并校验数量，再 rename（跨盘降级拷贝）换入本地，换入失败自动从恢复前快照回滚。
6. 报告增加 `elapsedMs`（设置页显示耗时）；恢复预览显示坏条目告警。

## 测试

- 单测 `skills-sync.test.ts` 新增安全阀用例（空本地不清远端、空远端拒绝恢复），5/5 过；全量 186 passed；typecheck 仅存量 3 错；mock UI E2E 过。
- 真实 WebDAV：沙箱闭环联测过；**用真实 /jeff（531 文件）跑 stage：148.5s 成功完成**（旧版卡死 5 分钟），20 个坏条目全部正确跳过并告警。
- 服务端并发能力实测良好（200 并发 GET 8.6s 零错误），挂起属偶发，重试兜底。
