# 定时任务完成后没有文本/声音提醒

- 日期：2026-09-17
- 范围：Jeff v1.8.16 → v1.8.17（PATCH）
- 现象：Windows 上任务完成后既没有桌面通知、也没有提示音（Linux 同样会复现）

## 一、根因

不是 Windows Toast / 提示音实现坏了。常规聊天回复的提醒链路完好：

- 原生通知一律 `silent: true`，声音由渲染层自己播（`notify.ts`）
- Windows Toast 前置条件满足：`app.setAppUserModelId('com.jeffxuu.jeff')` 与 `electron-builder.yml` 的 `appId` 一致，NSIS 安装器会用 `WinShell::SetLnkAUMI` 把同一个 AUMID 写进开始菜单快捷方式

真正的缺口：**定时任务（cron）触发的回合从未接入 `notifyTurnDone()`**。

`notifyTurnDone()` 同时驱动提示音和桌面文本通知，是唯一入口，原先只在两处被调用：

- 私聊 `sendAgent`（用户在渲染层点发送，`await api.invoke` 返回之后）
- 群聊 `sendGroup`（同上）

定时任务由主进程 `CronScheduler` 自主触发，走 `JeffCore.runCronTask()` → `privateChat.send()` / `groupChat.send()`，完全绕开渲染层发送函数。渲染层能收到的只是 `chat-updated` / `group-updated` / `cron-updated`，这些分支只刷新界面，从不响铃、不弹通知。

所以任务到点、真的完成、消息也真的落库了，但文本和声音会**同时**缺失——两个渠道共用同一个从未被触发的入口。这与操作系统无关，只是恰好被在 Windows 上使用定时任务的场景撞到。

## 二、修复

在调度器真正跑完（产出一条新消息）之后补一条信号，一路转发到渲染层复用现有提醒逻辑：

```
CronScheduler.execute 成功
  → onTurnDone(task)
  → JeffCore bus.emit('cron-turn-done', { kind, id })
  → main broadcast
  → store 拉最新历史
  → notifyTurnDone（声音 + 桌面通知）
```

改动：

- `packages/core/src/cron/scheduler.ts`：`CronSchedulerDeps` 新增 `onTurnDone`；仅 `runTask` 成功、`finish(ok)` 之后调用。失败、跳过、目标缺失、群未设群主都不调。回调自身抛错只记日志，不影响调度。
- `packages/core/src/index.ts`：接上 `onTurnDone`，把 `target_type`（`agent`/`project`）映射成 UI 用的 `agent`/`group`。
- `apps/desktop/src/main/index.ts`：转发 `cron-turn-done`。
- `apps/desktop/src/renderer/src/store.ts`：收到事件后先拉历史再 `notifyTurnDone`，摘要取刚落库的正文。群聊不传 `threadId`：定时任务发到当前活跃话题，缺省即按「命中当前会话」处理。

正盯着该会话时仍不打扰（沿用 IM 惯例）；窗口在后台或看别的页时响铃 + 按设置弹桌面通知。
