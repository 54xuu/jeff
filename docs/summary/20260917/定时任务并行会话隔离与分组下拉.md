## 三、找到的 bug 与修复

### 1. 新建任务目标下拉没有分组（用户已知）

原先两个字段：先选「私聊某个智能体 / 项目群」，再选具体目标。改成**一个下拉**，`<optgroup label="智能体">` / `<optgroup label="项目群">`，值为 `agent:<id>` / `project:<id>`。

### 2. 私聊定时任务与用户手打共用同一条 opencode 会话

`runCronTask` 原先走 `privateChat.send()`，kv 键是 `session:private:<agentId>`。两个早报打到同一个助手时，上下文会混在一起；用户正在聊的窗口也会被定时消息冲进去。

修复：每个任务一条专属会话，kv `session:cron:<taskId>`。`PrivateChat.sendDedicated` 不碰用户的会话指针，也不走该 agent 的停止/在途标记，所以用户点停止不会误杀定时任务，两条定时任务可以并行。

同一任务反复触发仍复用自己那条（早报跨天连续）。

### 3. 群聊定时任务写进用户当前正在看的话题

`groupChat.send()` 原先用 `ensureActiveThread`。用户在话题 A 里聊天时，定时任务会把「晨间问询」写进 A；两条群任务也会挤在同一个 thread。`createThread` 还会把新话题设成 active，等于抢走窗口。

修复：每个任务一条专属话题，kv `cron:thread:<taskId>`；`createThread(..., { activate: false })`；`send({ threadId })` 不改 active。消息仍带 `meta.cron_task_id`。

同一项目群内流水线仍按项目串行（共享工作空间，防文件/git 竞争）；不同智能体 / 不同项目可以并行，调度器并发上限仍是 2。

### 顺带：完成后提醒不再刷错窗口

工作区里已有的 `cron-turn-done`（v1.8.17 提醒缺口）继续保留，但改为**不重拉用户当前聊天**。通知标题用任务名、正文「定时任务已完成」，避免把用户正在看的会话摘要当成定时回复。
