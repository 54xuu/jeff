# 消息提醒（文本 + 声音）——Windows / Linux 双平台

- 版本：v1.7.30
- 日期：2026-09-13
- 验收：`npm test` 189 passed / `npm run typecheck`（仅 3 个存量 e2e helper 报错）/ `npm run test:e2e` 绿 /
  真实模型 E2E `live-notify` R1–R4 全绿 / Linux 侧 D-Bus 抓包坐实真的发出系统通知

## 1. 需求

AI 回复完成时给用户**文本提醒**（系统桌面通知）与**声音提醒**（提示音），Windows 与 Linux 都要好用。声音自备。

## 2. 关键设计决定

### 2.1 声音为什么不由系统通知负责

Linux（GNOME/KDE）的系统通知默认**不带音效**，Windows 的通知音又受「免打扰 / 通知声音」开关影响。
把声音交给系统，会出现「同一个应用在有的平台响、有的平台不响」。

所以：原生通知一律 `silent: true`，**声音由应用自己播**（渲染进程 HTML5 Audio）。
好处是两端音色完全一致；「关掉提示音」就是彻底安静，行为可预期。

### 2.2 提示音怎么来的

仓库里带一枚自研音效 `apps/desktop/src/renderer/src/assets/sounds/notify.wav`（73 KB，mono 44.1 kHz，0.85 s），
由一次性脚本 `.tmp/gen-notify-wav.mjs` 生成：两枚柔和钟琴音 A5→D6，各自叠 4 个非整数倍泛音
（1× / 2× / 3.01× / 4.2×），泛音倍频越高衰减越快（真实钟体的物理行为），起音 6 ms 升余弦包络防爆音，
峰值归一到 0.72，尾部再乘一次淡出避免收尾咔哒。

自己合成而不是下载音效的原因：零版权风险、零外链依赖、体积小、音色可调；
`notify.ts` 里还留了 Web Audio 现场合成同一个双音铃的兜底（音频文件解码/播放失败时用）。

### 2.3 提醒时机：对齐 IM 桌面端惯例

| 用户状态 | 提示音 | 桌面通知 |
|---|---|---|
| 正看着这个会话（窗口在前台 + 停在聊天页 + 选中的就是它） | ✗ | ✗ |
| 窗口在前台，但在看别的会话 / 别的页 | ✓ | 默认 ✗（可关掉「仅后台提醒」放开） |
| Jeff 在后台（最小化 / 被遮挡 / 切到别的虚拟桌面） | ✓ | ✓ |

- 判定「窗口在不在前台」用 `document.hasFocus() && !document.hidden`（最小化时 `document.hidden` 为 true）。
- 群聊还要求**会话（thread）也对得上**：用户切到同一个群的下一个话题时，旧话题的回复算「没在看」。

### 2.4 触发点是「一轮发送真正结束」，不是流式 done

这一点是整个功能最容易做错的地方。`chat-stream` 的 `done: true` 在群聊里**每一跳都会来一次**
（群主派发 → worker 汇报 → 群主总结，实测一轮 2~5 跳）。按它提醒，用户会被轰炸 2~5 次。

实际触发点选在 `sendAgent` / `sendGroup` 里 `await api.invoke(...)` 返回之后 ——
群聊的 `group:send` handler 是等**整条协作流水线跑完**才 resolve 的，一轮只提醒一次。
实测 R2：群聊一轮跑了 2 跳（资料员汇报 + 值班助手验收总结），只产生 1 条通知。

### 2.5 Linux / Windows 各自的坑

- **Windows**：Toast 通知必须带 `AppUserModelId`，否则静默丢弃。在 `app.whenReady()` **之前**（模块顶层）
  `app.setAppUserModelId('com.jeffxuu.jeff')`，取值与 `electron-builder.yml` 的 `appId`、
  安装器写入的开始菜单快捷方式 AUMID 保持一致。
- **Linux**：无默认音效（因此自己播声）；通知是否弹出取决于会话总线上的通知服务，
  `Notification.isSupported()` 为 false 时降级为只响提示音，不报错、不影响聊天。
- 开发态（未打包）在 Windows 上跑，AUMID 与快捷方式对不上时 Toast 可能不显示，属 Electron 已知限制，
  以**安装后的包**为准。

### 2.6 点击通知

主进程 `notification.on('click')` → `focusMainWindow()`（还原最小化 / 显示 / 抢焦点）→
`broadcast('navigate-chat', { kind, id })` → 渲染层切到对应私聊或项目群（ChatWindow/GroupWindow 挂载时自己拉历史）。

## 4. 踩过的坑

1. **`false` 不能当真值判断**：`if (notifySound) kv.set(...)` 会让「关掉提示音」永远存不进去。
   读写都改用 `typeof x === 'boolean'`。
2. **同步导入侧要区分「没这个键」和「值是 false」**：老备份里没有 `settings:notifySound`，
   如果写成 `d.notifySound ?? true` 会被旧值覆盖；改成只在 `typeof d.notifySound === 'boolean'` 时才写。
3. **提醒是收尾副作用，绝不能污染发送结果**：`notifyTurnDone` 的调用点在 `sendAgent` 的 `try` 里，
   一旦它抛异常会被 `catch` 当成「发送失败」弹给用户。整个函数体包了 try/catch 兜底。
4. **E2E 观测通知时，不能替换 `electron.Notification`**：主进程 bundle 是 ESM，
   `import { Notification }` 拿到的是活绑定，替换模块属性不会报错但对已 import 的引用**无效**
   （实测 `__notes` 始终为空，白等 8 分钟）。
   正确做法是补丁 `Notification.prototype.show` / `.on`：被测代码路径不变，只是不真弹、并把 click 回调记下来手动触发。

### 5.3 Linux 系统通知实证

`dbus-monitor --session "interface='org.freedesktop.Notifications'"` 抓包，调用 `notify:desktop` 后
捕获到 `org.freedesktop.Notifications.Notify` 方法调用，`summary="Jeff 通知联测"`、`body="dbus 抓包验证"`，
`Notification.isSupported() === true`，invoke 返回 `{ok:true}` —— 确实发出了 freedesktop 原生通知。

### 5.4 提示音资源实证

即：资源打进了 bundle、URL 能解析到真实文件、音频能被解码播放（不是只调了个 `play()` 就失败）。

## 7. 已知限制 / 后续可做

- 未做任务栏角标 / 未读红点：窗口在前台看别的会话时只有声音，靠用户自己注意左侧列表。
