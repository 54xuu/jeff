# 私聊 / 定时任务路径：渲染视频等长阻塞会 10 分钟超时（v1.8.14）

## 现象

v1.8.13 已经把**项目群**和 **jeff_delegate 委派回合**的等待预算从 30 分钟提到 90 分钟，能撑过多页截图、写总结这类长任务。但用户追问：渲染视频会更长（2–5 分钟，或更久），AI 等脚本执行时会不会再被超时掐掉、界面报错？

会。只是换了条路径：

- 私聊（1:1 跟某个智能体聊天）
- 定时任务 → 直接打给某个智能体（非项目群）

这两条都走 `PrivateChat.send` → `OcClient.sendMessage`，而 `sendMessage` 的默认预算仍是 **10 分钟**（`600000`）。一源多出 `publish` 在单次 `bash` 里同步轮询，默认 `--timeout` 长达 1800 秒（30 分钟）。只要这一步落在私聊或「定时任务→智能体」里，加上前后模型思考，总时长很容易越过 10 分钟，界面就会出现「等待 assistant 回复超时」——和白天产品宣传群那条报错是同一类，只是群聊已经修过、私聊漏了。

## 根因

`packages/core/src/oc/client.ts` 的 `sendMessage` 默认值写死 `600000`。群回合显式传了 `GROUP_TURN_TIMEOUT_MS`（90 分钟），私聊没传，定时任务打给智能体时复用 `privateChat.send`，于是继续吃 10 分钟默认值。

## 修复

- 抽出共享常量 `DEFAULT_SEND_TIMEOUT_MS = 90 * 60 * 1000`，`sendMessage` 默认值改用它（忘记传 `timeoutMs` 的调用方也不再掉回 10 分钟）。
- `GROUP_TURN_TIMEOUT_MS` 改为引用该常量，去掉第二份魔数。
- `PrivateChat.doSend()` 显式传入 `timeoutMs: DEFAULT_SEND_TIMEOUT_MS`，覆盖私聊与定时任务→智能体两条路径。
- 委派器过期注释「30 分钟总预算」改为 90 分钟。

记忆自省（`timeoutMs: 120000`）等短预算调用不受影响。

## 验证

- `@jeff/core` 单测 280 通过（含私聊显式传 90 分钟、`sendMessage` 不传时走默认值）。
- core / desktop 包级 typecheck 通过；根 tsconfig 仍有 3 个存量 e2e helper 报错，改动前就在。
- mock UI E2E + v18 全绿。

## 不在本次范围内

`bash` 工具单次调用的 timeout 由模型在调用时自己传，属 opencode 内置工具行为，Jeff 不写死。若模型给 `publish` 传了一个过短的 bash timeout，仍可能在脚本内部被掐断——那一层需要 skill 提示，不属于本仓库版本管理。
