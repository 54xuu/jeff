# Desktop 与 App 界面交互优化方案及验收计划

日期：2026-10-06

状态：方案 A 已实施并完成可执行验收；Android 与远程真实链路存在未验证项，Windows 包尚未在 Windows 机器安装。

## 目标与已确认方向

App 的首要用途是随时与智能体、项目群聊天，采用微信式的简洁交互，保留 Jeff 翡翠色和小杰形象。本轮重点优化 App；desktop 保留三栏结构，配合统一视觉与操作语义。

| 区域 | 优化方案 |
| --- | --- |
| 导航 | App 底部为聊天 / 通讯录 / 我；电脑连接、绑定、外观与设置放在我页 |
| 聊天首页 | 智能体、项目群最近聊天混排，按最新消息排序，支持置顶；分组作为筛选，提供搜索和发起聊天 |
| 通讯录 | 保留智能体、项目群分组；没有最近消息的对象也能找到并发起聊天 |
| 消息 | 用户右侧淡绿气泡；助手带头像、名字，正文无外框展开，适配长回复、表格与代码 |
| 执行过程 | 默认一行进度摘要，按需展开思考与工具详情；失败与授权请求直接提示 |
| 操作 | 输入框加号仅负责图片、文件等附件；顶栏更多负责会话管理；项目群保留工作区入口 |
| 工作区 | 首屏为待办、待确认成果、最近文件；具体功能进入详情页，新增与编辑按需打开表单 |
| Desktop | 统一头像、颜色、进度摘要与按钮含义，保留三栏和已有能力 |

视觉整理重点：统一文字层级、间距、头像和线性图标，减少重复状态标签和不必要的彩色图标底块。先完成导航与聊天列表，再完成聊天页、项目工作区，最后对齐 desktop。

## 验收原则

自动测试负责可测行为；截图对照和人工审阅负责外观；Android 安装运行和真实通信负责系统行为。任何一类都不能替代另外两类。

先固定代表页面、数据和验收标准，再实施。产品效果以经用户确认的实际预览为依据；不能用当前实现重新生成基准来消除差异。存在阻断问题时不进入打包。

## 第一阶段：建立视觉基准

1. 保存当前代表页面截图，记录既有行为与需要改善的点。
2. 制作可点击的聊天列表、聊天页、工作区概览三屏预览，包含列表进入聊天、打开菜单、进入工作区的操作。
3. 用户确认视觉方向后，记录字号、行距、页面间距、头像尺寸、图标风格、颜色、圆角、控件高度和状态布局，形成实施基准。
4. 实施后使用相同数据、尺寸、主题与状态进行前后对照；字体环境固定，时间与动态动画固定或屏蔽，减少截图噪声。

通过标准：用户认可三屏的密度、阅读体验与风格；所有设计项有明确取值。后续新增页面遵循该基准，重大视觉偏离需要重新对照确认。

## 第二阶段：视觉与操作验收

### 视觉覆盖

- App 核心页面按 360×640、390×844、412×915 CSS 像素，分别检查亮色和暗色。
- 覆盖聊天列表、通讯录、我页、私聊、群聊、附件面板、更多菜单、工作区概览和编辑页。
- 边界状态覆盖长名字、空列表、未绑定、多电脑、离线、长 Markdown、表格、代码、图片、流式执行、失败、待授权。
- 普通正文建议不小于 16 CSS px；主要触控目标至少 44×44 CSS px。Android 放大字体后，内容与控件仍能访问。
- 无页面级横向溢出、文字重叠、操作遮挡；表格与代码可在自身容器内横向滚动。
- 小屏、暗色和系统安全区下，发送、返回、菜单与底部导航可见且可用。
- Desktop 检查常规与窄窗口、亮暗主题、左右栏收起展开，以及至少一种非整数系统缩放；分栏偏好宽度不被临时窗口缩小覆盖。

### 关键操作与通过标准

以下点击数从指定起点计算，不包含输入文字、权限确认和系统文件选择步骤。

| 操作 | 通过标准 |
| --- | --- |
| 从聊天首页继续对话 | 点击列表项一次进入；最近排序、置顶、未读显示与清除正确 |
| 找到未聊过的对象 | 通讯录分组或搜索能找到所有可用智能体、项目群并发起聊天 |
| 打开附件选择 | 从聊天页一次点击打开加号面板；只展示发送相关动作 |
| 搜索或切换会话 | 从聊天页最多两次点击到相应操作界面；切换后消息和草稿不串会话 |
| 查看执行详情 | 一次点击展开；执行状态准确，完成后正文和详情仍保留；失败与授权不被折叠隐藏 |
| 查看工作区待办与成果 | 从群聊一次进入概览，直接看见待办、待确认成果和最近文件；不存在内容时显示明确空态 |
| 进入新增或编辑 | 从相应详情列表按需打开表单，概览不堆放完整配置表 |
| 返回与关闭 | Android 返回键先关闭键盘或最上层面板，再按页面层级返回；返回不丢当前对话、草稿与必要浏览位置 |
| 切换电脑 | 当前设备和状态明确；不同电脑的缓存、消息、草稿不混用 |

自动断言覆盖导航、排序、筛选、置顶、未读、返回层级、展开收起与入口归属。至少录制一次首页继续聊天、通讯录发起聊天、群聊进入工作区的完整路径供人工检查。

通过标准：覆盖场景全部通过；逐张检查代表截图并记录结果；无阻断操作、内容丢失或偏离确认基准的问题。

## 第三阶段：Android 与真实链路验收

日常优先使用项目规定的 Android AVD `jeff`。浏览器 viewport 缩小不能替代软键盘、系统返回、安全区和原生附件选择的验证。

在安装后的 App 上验证：打开和收起软键盘、输入多行内容、发送按钮位置、附件选择取消、Android 返回、锁屏恢复与断线重连。真实手机补验应安排在发布验收阶段，避免日常占用设备；没有完成时明确标记为未验证。

通过真实 App—中转—desktop 链路验证私聊与群聊：发送、接收流式正文、工具进度、停止、失败、授权、切换会话与重连。涉及真实模型的状态使用真实 sidecar 与模型；固定事件用于稳定复现错误和授权等边界。

不只断言 DOM：对照 desktop 落库历史中的 text、reasoning、tools，验证流式期间内容完成后仍在；任务变更检查数据库，文件与成果检查真实文件。确认不重复消息、不串会话、不抢其他任务的会话。

通过标准：Android 系统行为和真实链路均有运行证据；关键内容与服务端事实一致。外部模型或网络阻塞单独记录，不能标为通过。

## 第四阶段：回归、打包与产物验收

复用并扩展现有测试，保留有效的行为断言。导航变化可以调整定位方式，不能放宽断言掩盖功能回退。

- App：`npm run test -w @jeff/mobile`、`npm run build -w @jeff/mobile`、`npm run test:e2e -w @jeff/mobile`。
- 仓库：`npm test`、`npm run typecheck`。既有类型错误记录基线，本次新增错误必须修复。
- Desktop：mock UI E2E，以及 `v18`、`cron` 封闭套件；涉及聊天与执行状态的修改还需真实模型 E2E；涉及远程行为运行并补充 remote 覆盖。
- 同一发版意图只升一次版本，遵循仓库默认 PATCH 规则；若最终判断属于独立新能力需升 MINOR，则按仓库规则先确认。
- 本轮预期同时修改两端，产出 APK、Ubuntu deb/AppImage、Windows exe。APK 用 `aapt dump badging` 核对版本，安装到 AVD 验证。
- deb 安装后核对版本，以及 `/opt/Jeff` 与打包目录的 app.asar MD5 一致。
- exe 检查 PE32 Nullsoft 类型、本次改动特征在 app.asar 中、Windows opencode.exe 在位。本机 Wine 弹窗不作为验收门；Windows 真机安装若未完成，明确报告未验证。

通过标准：要求的检查全部完成且无新增失败；每个安装包可定位、有版本与产物证据；任何未验证项明确列出，不能宣称全面通过。

## 证据与最终交付

临时预览、截图、操作录像、日志和数据对账放在仓库 `.tmp/`，按阶段组织并提供证据索引；长期方案与结果继续更新本文件并提交 Git。

最终验收表逐项记录：目标、通过标准、自动测试结果、人工审阅结果、证据路径和未验证事项。分别列出“视觉达到基准”“操作路径通过”“真实链路通过”“安装包验证通过”，不以单一测试通过数代替完成判断。

## 实施记录（2026-10-06）

用户在三屏可点击预览中选择了**方案 A：熟悉的聊天列表**。该选择作为视觉基准；原型仍留在独立原型分支，不把方案 B/C 的切换器或原型代码带入产品。

当前实施内容：

- App 底部导航改为「聊天 / 通讯录 / 我」。聊天页只呈现小杰、置顶项和已有最近消息的会话，智能体与项目群按置顶、最近活动混排；支持类型筛选、搜索、长按置顶。通讯录保留全量项目群和智能体分类，搜索结果可直接打开会话；从联系人发起聊天后返回聊天首页。
- 聊天顶栏收纳查找、切换/新建会话、上下文和工作区文件操作；加号面板保留图片入口。Android 返回按「文件预览 → 工作区概览 → 聊天」逐层返回。
- 项目群的工作区首屏改为概览，汇总未完成任务、待验收交付、待确认素材和最近文件；目标、报告、任务、素材、成品表单按需进入详情。项目 Markdown 预览返回原工作区。
- Desktop 保留三栏和原有能力，群资料入口名称统一为「项目资料」，使桌面与 App 的工作区概念一致。
- 代表截图保存在 `.tmp/e2e-screens/`：`01-list.png`、`13-contacts.png`、`14-project-overview.png`、`15-project-profile.png` 等。全量验收完成后更新下面的验收表和未验证项。
