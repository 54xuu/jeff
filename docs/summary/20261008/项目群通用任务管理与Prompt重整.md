# 项目群通用任务管理与 Prompt 重整

日期：2026-10-08。

## 本轮结果

按用户要求调用 `grill-me` 技能；实际文件要求进入 `grilling` 逐题讨论。已通过讨论确认产品边界，并基于当前源码形成可审阅的技术与验收方案：

[项目群通用任务管理与 Prompt 重整技术方案](../../notes/20261008-项目群通用任务管理与Prompt重整技术方案.md)

## 已确认的决定

- 删除未使用、未保存数据的项目工作台及销售/宣传等专用业务，不归档或迁移旧工作台数据。
- 通用任务使用三个独立、可选文本域：目标、任务描述、验收标准。
- 创建只保存；用户点击开始执行后由负责人执行，未指定时由群主协调。每项任务独立话题。
- 智能体提交结果进入待验收；用户通过才完成，退回可继续执行，失败/中断保留原因。
- 项目群资料采用项目管理、群资料、群成员、会话记录、工作区文件五个入口，两端一致。
- Prompt 各设置区分含义与作用域；普通回合、委派及群内子任务共用组成逻辑，预览对账实际发送内容。
- 用户认可剩余细节采用推荐方案，要求尽快出技术方案；产品代码仍等待方案最终确认后实施。

## 静态核查发现

普通群回合已注入群简介、规则、成员职责和记忆/AGENTS.md，不能说这些设置全部失效。主要缺口是群内独立子任务未接入完整群上下文和群成员模型覆盖、上下文预览只展示部分 system、旧阶段目标不直接进入普通群 Prompt。

当前任务主要提供保存与状态流转，没有专用开始执行服务；通用任务更新路径可写 done。因此新增任务执行与人工验收需要后端状态/调用来源约束，不能只改 UI 或补 Prompt。

远程白名单实现当前有默认 allow 分支；本次新增通道必须显式归类和测试，不能依赖注释认为漏项一定会失败。

## 方案包含

任务数据与本机运行边界、状态机、幂等和停止、负责人 ID 路由、任务话题隔离、提交版本与人工验收、WebDAV 同步边界、Prompt 组成与引擎适配、桌面/手机 UI 状态、旧功能删除清单、实施模块、单测/封闭 UI/真实模型测试矩阵、三平台正式产物及安装验收。
