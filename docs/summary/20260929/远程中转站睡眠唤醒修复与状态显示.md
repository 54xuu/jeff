# 修复远程中转站睡眠唤醒重连与增加连接状态显示

版本：1.9.6（PATCH）

## 1. 问题背景与根因

### 现象
1. 晚上将 Windows 电脑睡眠，第二天唤醒后，电脑端 Jeff 可以正常使用，但手机 Android App 一直显示「电脑离线」黄色警告，无法进行远程操作。
2. 电脑端「设置 → 远程控制」仅显示一行静态的「中转站已连接」或「正在连接中转站」，无法获知中转站实际连通状态、延迟或进行手动重连。

### 根因排查
1. **系统睡眠挂起与 TCP 半开（Half-Open）**：
   - Windows 睡眠后网络被系统挂起，TCP 物理连接中断，但系统**不会**向云端中转站（ECS）发送 TCP FIN/RST 分节。
   - 阿里云 ECS 中转站或 NAT 防火墙因长时间无流量触发超时关闭连接，中转站触发 `disconnect`，向手机端推送了 `presence: online=false`。
2. **桌面端未感知底层断连，进入僵尸连接**：
   - 电脑第二天唤醒后，Node.js `ws` 套接字未感知底层连接已断开，`ws.readyState` 停留在 `OPEN`，`RemoteGateway.connected` 仍为 `true`。
   - 桌面端此前**没有主动周期性心跳探测（Ping/Pong）**，亦未监听系统电源事件（`powerMonitor.on('resume')`），导致桌面端既不发包、也不重连，陷入僵死状态。

---

## 2. 修复方案与改动

### 2.1 桌面端主进程（RemoteGateway）休眠唤醒感知与主动心跳
- 文件：`apps/desktop/src/main/remote/gateway.ts`
  - **监听系统电源事件**：
    - `powerMonitor.on('suspend')`：系统睡眠前主动释放连接与心跳定时器。
    - `powerMonitor.on('resume')`：系统唤醒时，主动抛弃旧的失效套接字，标记状态为 `connecting`，延迟 1.5 秒（等待系统 Wi-Fi/网卡重新获得网络 IP）后触发自动重连。
  - **启用主动心跳检测**：
    - 连接就绪后，启动 20 秒周期的心跳定时器（`ws.ping()`）。
    - 收到 `pong` 时记录往返延迟 `rttMs`、更新 `lastPingAt` 并广播到渲染层。
    - 若发出 ping 后 10 秒内未收到响应，判定为半开挂死连接，主动执行 `ws.terminate()` 触发重连机制。
  - **支持手动重连通道**：
    - 注册 `IPC.remoteReconnect`，供用户在界面上一键重置连接。

### 2.2 协议与白名单扩展
- 文件：`packages/core/src/ipc/contract.ts`、`packages/core/src/remote/whitelist.ts`
  - 为 `RemoteStatus` 扩展 `relayUrl`、`state`、`rttMs`、`lastPingAt`、`lastConnectedAt` 等诊断字段。
  - 新增 `IPC.remoteReconnect` 通道，在 `REMOTE_POLICY` 白名单中归为 `deny`（仅允许电脑本地操作）。

### 2.3 电脑端界面优化
- 文件：`apps/desktop/src/renderer/src/components/settings/RemoteSettings.tsx`、`apps/desktop/src/renderer/src/styles.css`
  - 增加中转站连接状态卡片：
    - 状态指示灯（绿色已连接 / 黄色连接中 / 红色连接失败）。
    - 展示中转站地址（如 `wss://47.106.209.32:9443`）。
    - 实时显示心跳往返延迟（如 `38 ms`）与本次连通时间。
    - 提供「重新连接」按钮，方便在切换网络或异常时手动恢复。
