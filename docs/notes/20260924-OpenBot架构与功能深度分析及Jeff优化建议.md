# OpenBot 架构与功能深度分析，以及对 Jeff 的优化建议（2026-09-24）

> 源码考察对象：`~/Documents/github/OpenBot`（CopilotKit/OpenBot，MIT，仓库版本 `0.0.15`，Alpha）。
> 对照产品：Jeff 桌面应用（本仓库，考察时版本 `1.8.28`）。
> 本文只记录值得 Jeff 借鉴的部分。语音听写、常驻语音通话、预置 SaaS 连接器目录这三块本次不纳入建议。

## 1. OpenBot 是什么

OpenBot 是一份可克隆的企业助理模板，不是托管产品。形态接近 ChatGPT / Claude 的工作台，差别在于整套跑在自己的机器上，智能体后端可以换成任何说 [AG-UI](https://github.com/ag-ui-protocol/ag-ui) 的端点（LangGraph、Mastra、CrewAI、手写皆可）。治理挂在协议上，不挂在某一个框架上。

仓库是 Bun workspace：`app`（React 19 + Vite + TanStack Router/Query）、`server`（Hono API）、`worker`（定时扫描）。数据在 PostgreSQL（带 pgvector）。每个 Bot 可以有一台自己的电脑：独立容器里的 Chromium、登录态和 `/workspace`，由 `supervisor` 创建和回收。模型密钥由管理员提供，加密落库，不进日志。

一条回合的路径：

1. 界面打开频道或直连某个 Bot。
2. 服务端认出当前用户和选中的 coworker。
3. CopilotKit runtime 把回合送到该 Bot 的 AG-UI 端点。
4. 前端按授权注册本回合可用的工具：浏览器、MCP、已授权的界面组件。
5. 真正去点浏览器、改文件、调 MCP 的调用先回到服务端：解析目标、对策略做决定、写审计，允许了才执行。
6. 结果流回界面，线程落在 CopilotKit Intelligence。

## 2. 和 Jeff 已经对齐的部分

这些能力两边都有，形态不同，不构成「Jeff 缺了」：

| 能力 | OpenBot | Jeff |
|---|---|---|
| 多智能体 | coworker 档案 + 频道；`message_bot` 显式转交 | 智能体私聊 + 项目群，群主拆解后 `@` 派发，成员汇报后群主总结 |
| 定时任务 | Routine：对话里用句子创建，worker 进程到点触发 | `jeff_cron_*`：小杰对话或定时页创建，进程内调度器到点向私聊或项目群发消息 |
| 错过的触发 | 过期窗口直接跳过，不补跑积压 | `miss_policy`：`skip` 跳过并记 `missed`，`catchup` 开机后补跑一次 |
| 插件 / 外部工具 | 目录插件 + 按 Bot 授权；Composio 代持账号 | `~/.jeff/plugins` 清单，启用即注入 MCP，每插件一条 `/` 指令 |
| 内置浏览器 | 每 Bot 一台容器里的 Chromium，截图轮询 + 接管时 CDP 投屏 | 右侧同一块 webview，人与智能体操作同一页，`jeff_browser_*` |
| 会话名称 | 后台另调一次小模型，3 到 6 个词 | 首条用户消息抽出任务名，格式 `{YYYYMMDD-HHmm}-{任务中文名称}`，只改一次 |

Jeff 的群协作、定时任务会话隔离、插件结构化落盘，比 OpenBot 示例包更贴「一个人用的桌面工作台」。下面只写 OpenBot 里 Jeff 还没有、并且用得上的机制。

## 3. 值得优化的地方

### 3.1 内置浏览器：卡住时请人接手

OpenBot 把「人看着」和「人接手开」分成两档。

- 平时看屏幕用低频截图，便宜。
- 人点「接手」之后改走 Chrome screencast WebSocket。帧用 `createImageBitmap` 在主线程外解码再画到 canvas，避免每帧同步解码把页面卡死。鼠标坐标按截图的自然尺寸换算回页面坐标（`pageCoordinates`）。键盘修饰键按 CDP 的位掩码转发（Alt 1、Ctrl 2、Meta 4、Shift 8），否则按住 Shift 打出的大写会变成小写。粘贴不把 Ctrl+V 的字面量送过去，而是读本地剪贴板再转发，这样俄文、希腊文键盘上的 V 键也不会丢。
- `useNeedsYou` 每 3 秒看一次该 Bot 的控制状态。浏览器在要密码、要验证码时把 `requested` 或 `secretWanted` 置上，频道里即使屏幕是收着的也能亮出「需要你」。

Jeff 的内置浏览器已经是人和智能体共用的同一块 webview，人本来就能点。缺的是契约：智能体撞上验证码、登录墙或双因子时，工具没有一个稳定的「停下来等你、你做完再继续」状态。现在多半是模型在正文里说明，或者反复重试直到超时。

建议落在现有浏览器栏，不必另做一套投屏：

- 工具侧增加「等待人工」结果。智能体调用点击 / 填表失败且页面像登录或验证码时，返回这个结果并停下，不把失败当成可以自己重试的普通错误。
- 浏览器顶栏在这个状态下显示「需要你操作」。人在 webview 里做完后点「继续」，把当前页面地址和一句简短说明送回正在等的那一轮。
- 没有进行中的浏览器工具时，顶栏保持现在的样子。

### 3.2 流式回复的静默看门狗

OpenBot 的 `stall-guard.ts` 盯的是 Bot 自己的 HTTP 响应体，不是界面上的加载动画。

它故意做成恒等转发：不缓冲、不等待、不解析字节。缓冲会把逐 token 的回复攒成一整段才出现；在转发器里打时间戳会把「下游消费者暂停」误判成「Bot 沉默」。计时放在从 Bot 读下一块的那一侧，下游还没取走时停表。静默超过配置的 `stallMs` 就往同一条流里写一条 `RUN_ERROR` 然后关掉。超时设成 0 或更小则包装器根本不挂上，部署保持旧行为。内容类型只排除 protobuf（`application/vnd.ag-ui.event+proto`），其余都按 SSE 看，避免比客户端更严、把还在正常输出的流掐掉。

Jeff 在 v1.8.27 已经能在用户点停止时立刻掐断挂起的请求。还没覆盖的是另一头：连接没断、也不报错，只是长时间不再吐字。输入框会一直停在生成中。

建议：在 sidecar 流转发处加同一类零缓冲计时。静默超过约 30 秒时结束本轮，界面解锁，并留下一句「上游长时间没有新内容，本轮已停止」。用户主动停止、正常结束、工具步骤之间的短暂停顿都不算静默。计时只看「从上游读到下一块」，不看界面有没有把已收到的字画出来。

### 3.3 会话标题再短一截

Jeff 已经会用首条用户消息给会话起名，不再是「新会话」占位一直留着。OpenBot 多做了一步：首轮有内容之后，用一次独立的小模型调用起 3 到 6 个词的标题。这次调用不占线程锁，失败就保持原样，不挡用户的下一条消息。标题指令写的是规则（不要引号、不要句号、不要「关于某某的对话」这种前缀）， deliberately 不给例子，因为模型会把例子的主题一起抄走。

这不是替换 Jeff 现有的 `{时间}-{任务名}`。任务名来自首条消息的截取，长指令会把侧栏撑得很宽。可以在现有命名之后，用同一次轻量调用把任务名收成几个字，时间前缀保留，调用失败则保持现在的截取结果。

### 3.4 定时任务：连续失败后自己停

OpenBot 把两件容易混在一起的事分开：

- 单次投递失败（队列忙、进程抖一下）由工作队列自己的重试次数处理，用户看不到。
- 「这个例行任务还值不值得再跑」由疲劳规则处理。失败只在「上一次是成功、这一次失败」时发一条消息，不每次失败都刷屏。连续失败 10 次就关掉，再发一条收尾说明。密钥过期这种错误重试不会好，只有停下来告诉人。

另外两条护栏：最短间隔 15 分钟（一句话可以说「每分钟」，代码不允许）；每人最多 20 个开着的例行任务。worker 每次扫描写一行 `routine_sweeps`，页面据此告诉用户「从来没有 worker 来查过」或「上次查是什么时候」。没有这个标记时，任务列表看起来完全正常，只是永远不会响。

Jeff 已有：到点入队、上一轮没跑完就记 `skipped`、目标被删就停用并写原因、`skip` / `catchup`、一次性任务跑完即停。没有的是「同一条任务连续失败 N 次后自动停用」。外部接口长期 401 时，任务会按 cron 一直记 `failed`。

建议只加疲劳规则，不加 OpenBot 的 15 分钟地板和 20 条上限（Jeff 的定时任务是用户在本机明确配的，不是模型被一句话哄出来的一长串）。连续失败阈值放在调度器里，成功一次就把计数清零。停用时写一条运行记录，并走现有的定时任务完成提醒，让人知道是被停掉的，不是漏跑。

### 3.5 回答要说来源

OpenBot 在每个 coworker 的 standing role 后面再加一段部署级说明：答案要说来自哪里；凭自身知识回答的要标明，不能装成查过资料。这段由部署追加，不写在某个 Bot 的人设里，新建 coworker 也不会漏。

Jeff 的智能体指令、项目 `AGENTS.md`、记忆块已经分层注入。可以在组装 system 的固定尾部加一条短约束：引用了工具或文件就指出是哪一次工具、哪个路径；没有查到就直说是推断。不改各智能体自己的人设文件。

## 4. 值得新增的功能

### 4.1 回合内的结构化卡片

OpenBot 的 gallery 是一组前端工具。模型调用后，界面不渲染 Markdown，而渲染一张卡片。组件用 `import.meta.glob` 收集，按名字排序后一次性注册 hook（数量不能在首屏之后变化）。服务端另存一份「这个部署允许这个 Bot 用哪些组件」；调用时再查一次，收回授权后旧的那次调用仍显示当初的卡片，新的调用显示拒绝原因。

和 Jeff 现有消息形态的差别：Jeff 的工具步骤是过程，正文是 Markdown。下面三种卡片是结果本身，人要在卡片上做完选择，回合才继续。

**审批卡片。** 参数是标题、一两句摘要、若干「标签 / 已格式化的值」、可选的按钮文案。卡片上有一个可选的理由输入框。人点同意或拒绝后，`respond({ decision, note })` 把选择交回被挂起的那一轮。完成后卡片不再显示按钮，只留「已同意 / 已拒绝」。适用：小杰要改设置、删插件、停掉一组定时任务之前。

**选择卡片。** 参数是问题和一组选项（id、标签、可选说明）。人点一项即回传 `{ choice, label }`。已选的高亮，其余变淡。适用：模型在问「用哪个智能体 / 哪一个目录 / 哪一种错过策略」，不必再打一句话。

**记录卡片和指标卡片。** 记录卡是标题、副标题、状态徽章和字段表，字段值换行显示，不截断。指标卡最多六个数字，每个可带「较上期」的变化和语气（中性 / 正向 / 提醒 / 负向）。数字由模型格式化后传入，界面不做单位换算。适用：病区概况、任务统计，比一大段列表好扫。

实现时沿用 Jeff 已经踩过的工具参数规矩：给模型的参数只用标量和标量数组；卡片上的「字段列表」若必须是对象数组，要在定义里写清楚，并在单测里锁住。空串当没传。人还没点之前，这一轮停在工具挂起，点停止要能取消，和 v1.8.27 的停止语义一致。

### 4.2 显式转交，以及转交时谁在场

OpenBot 的 `message_bot` 接受后，工具回包以固定前缀 `Handed to ` 开头；`ask_person` 以 `Put to ` 开头。前缀只声明一次，服务端和界面一起读。曾经三处各写一份，测试全绿，但界面把每一次成功转交都画成「已阻止」。

转交和定时任务都会在审计里写 `initiator_kind`：

| kind | 含义 |
|---|---|
| `person` | 有人在。默认值 |
| `routine` | 定时任务以创建者的身份跑，当时没有人看着 |
| `handoff` | 另一个 Bot 转过来的，权限仍是最初那个人的 |
| `deployment` | 进程自己的启动或拒绝，不算某人的工作 |

「没人看着」是 `routine` 和 `handoff` 合在一起的筛选。电脑操作不带这个字段，因为电脑工具不经过这套断言。

Jeff 的项目群已经有群主派发和成员汇报，那是群编排，不是私聊里把这一轮交给另一个智能体。建议：

- 增加一个显式转交工具，只在私聊可用。参数是目标智能体 id 和要它做的那一段说明（标量）。深度有上限，防止 A 转给 B、B 再转回 A。
- 转交使用目标智能体自己的模型和工具，不继承调用方不该有的能力。小杰仍然没有文件和命令工具，转交不能绕过这一点。
- 成功或拒绝用同一处常量前缀，界面和工具输出一起读，避免文案一改就画错。
- 定时任务触发的回合在运行记录里已经能区分。若以后做审计视图，再把 `initiator` 补上；这一步不单独做页面。

`ask_person` 和 3.1 的「需要你操作」是同一类停顿：模型问人、人答完再继续。浏览器场景走浏览器栏，其余场景走审批卡片或选择卡片，不再各做一套。

## 5. 本次明确不借鉴的部分

- **输入框语音听写、常驻语音通话。** OpenBot 有听写草稿和 WebRTC 语音浮层，语音模型再通过 `ask_agent` 把需要工具的句子交回原 Bot。本机几乎不用语音输入，不加入路线图。
- **Composio 式 SaaS 目录，以及现成的 GitHub / 飞书 / Notion 连接器模板。** OpenBot 用一个部署级 key 代持上百个应用的账号，管理员按 Bot 授权，每个人连接自己的账号。Jeff 的插件已经能装智慧病房这类专用能力，通用 SaaS 目录没有使用需求。
- **每 Bot 一台容器电脑、gVisor、CEL 策略语言、PostgreSQL 审计库。** 这些是多租户部署的边界。Jeff 是本机单用户，浏览器分区、插件启用开关和现有工具权限已经是边界。把策略引擎换掉的收益对不上迁移成本。
- **频道摘要的第二套标题系统整个搬过来。** 见 3.3：只考虑在现有命名上收短，不另建一套频道模型。

## 6. 建议的落地顺序

1. 定时任务连续失败自动停用。改动面在 `packages/core/src/cron/scheduler.ts` 和运行记录，有现成单测可加。
2. 流式静默看门狗。接在现有停止语义旁边，避免两套「结束本轮」互相打架。
3. 浏览器「需要你操作」。先做状态和继续按钮，不改截图和填表协议。
4. 审批卡片和选择卡片。先只给小杰的设置类工具用，确认挂起和停止之后再开放给普通智能体。
5. 私聊显式转交。排在卡片之后，因为转交过程中问人需要同一套挂起。
6. 会话名收短、回答来源约束。文案和一次额外模型调用，放在功能稳定之后。
