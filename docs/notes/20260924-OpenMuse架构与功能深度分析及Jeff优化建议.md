# OpenMuse 架构与功能深度分析，以及对 Jeff 的优化建议（2026-09-24）

> 源码考察对象：`~/Documents/github/openmuse`（CopilotKit/OpenMuse，MIT，Alpha，自托管模板）。
> 对照产品：Jeff 桌面应用（本仓库）。
> 本文只记录值得 Jeff 借鉴的部分。两阶段人工审批（Action Proposals）本次明确不纳入：Jeff 是本机完全控制的工作台，智能体直接执行，不设提案门禁。

## 1. OpenMuse 是什么

OpenMuse 是一份可克隆的个人助理模板，不是托管产品。形态是「把一件事交给助理，看它的计划，缺信息时补上，回来看结果」。界面用 CopilotKit 的 React Native headless hooks 一套代码覆盖 iOS、Android 和网页；服务端是 Hono，数据默认落在嵌入式 PGlite（可换 PostgreSQL）；浏览器是一个独立的 Playwright worker 进程；另有一个可选的 Docker Linux 容器当「电脑」。

一条回合的路径：

1. 界面用 `useAgent` 挂上一条会话，`copilotkit.runAgent` 把回合送到服务端的 CopilotKit runtime。
2. runtime 把模型调用转成 AG-UI 事件流回界面；工具结果不进 Markdown，由 `useRenderTool` 按工具名渲染成卡片。
3. 长任务不占这条会话：`delegate_task` 在服务端建一条 `AgentTask`，由 `TaskWorker` 持有租约执行，步骤、证据、产物都落库，进程重启后从检查点继续。
4. 会话本身的持久化交给 CopilotKit Intelligence（外部服务，要项目密钥）；没有密钥时退回服务端自己存的一份消息列表。

## 3. 值得优化的地方

### 3.1 生成期间继续打字，消息排队而不是被挡住

OpenMuse 的输入框在回复期间始终可编辑。`ConversationQueue`（`apps/mobile/src/conversation-queue.ts`）是一个纯前端状态机：`pending`、`running`、`paused`。正在回复时按下发送，文本进队列并立刻从输入框清空；当前回合结束后按顺序逐条发出。停止回复会 `pause()`，队列里剩下的不自动继续，要点「发送排队消息」才恢复。发送失败同样暂停，失败的那条已经在记录里，不会被隐式重发。

Jeff 现在生成期间输入框还能打字，但发送按钮换成了停止，`doSend` 在 `sendingNow` 时直接返回，打好的字只能干等。长回复时想追加一句「另外顺便……」没有去处。

建议落在 `ChatWindow` / `GroupWindow` 现有的 composer 上：

- 生成中按下发送时，把当前草稿（文本、引用、图片）推进本会话的队列，输入框清空，停止按钮保持原位。
- 队列画在输入框上方，每条可单独移除。
- 本轮正常结束后自动发下一条；用户点了停止，或本轮以错误结束，队列暂停，给出「继续发送」而不是自己往下冲。
- 队列只活在打开的窗口里，不落库。Jeff 的定时任务和群派发是另一条链路，不受影响。

### 3.2 工具结果渲染成卡片，而不是折叠的调用记录

OpenMuse 的 `useRenderTool` 按工具名注册渲染器：`browse_web` 画出带域名、读取状态、实时截图和「接管」按钮的卡片（`browser-tool-card.tsx`），截图地址是服务端现签的短时 URL，不写进消息；`TaskThreadCard` 把任务的计划步骤、关联浏览器会话、PDF 和产物各自画出来，重放历史时按任务 id 重新取，不依赖当时存在消息里的内容。

Jeff 的工具调用收在 `AssistantExtras` 的折叠块里，列出工具名和状态，输出是文本。看一眼能知道「调过什么」，看不出「拿到了什么」。

建议先做两张，都从现有落库数据渲染，不改工具协议：

- 浏览器卡片：`jeff_browser_*` 的调用显示地址、动作和结果摘要，点击直接打开右侧浏览器栏到该页。
- 文件卡片：工具输出里识别出的工作区文件路径（`linkify` 已经会识别）额外给一张可点击卡片，点开走现有的 Markdown 预览。

卡片是展示层。工具的参数、输出原文保留在折叠块里，排障时还查得到。

### 3.3 任务步骤的检查点与幂等

OpenMuse 的 `TaskWorker` 用 SQL 租约跑任务：领取时写入 `leaseId` 和 `leaseUntil`，执行中定期续约，租约过期的任务会被下一个 tick 重新领取。工具调用串行化（模型可以并行提请求，落库必须有序）。每个有副作用的工具调用先按「工具名 + 参数」算哈希，结果存进 `task.state.operations`，同一任务重跑时直接返回缓存，不重复执行。`compareAndSwap` 用 `data @> expected` 做条件更新，状态被别人改过时更新落空而不是覆盖。

Jeff 的群协作一轮里成员各自执行，中途进程退出后靠消息记录恢复上下文，但工具调用本身没有「这次已经做过」的标记。重跑时模型可能把同一个外部写操作再做一遍。

建议的范围收窄到项目群的派发：每个子任务记录已完成工具调用的哈希和结果摘要，恢复时把这份清单塞回上下文，并在工具桥层对同一哈希的重复调用返回上次结果。私聊回合保持现在的形态，不做任务化改造。

### 3.4 连续失败后自己停下

OpenMuse 的监控项把「一次失败」和「这个监控还值不值得跑」分开：失败次数记在任务 state 里，成功一次清零，连续失败后退避，达到阈值停止并留下一条说明。

Jeff 的定时任务已有：到点入队、上一轮没跑完记 `skipped`、目标被删就停用、`skip` / `catchup`、一次性任务跑完即停。没有的是同一条任务连续失败后的自动停用。外部接口长期不可用时，任务会按 cron 一直记 `failed`。

建议只加这一条：调度器里记连续失败次数，成功清零，连续失败达到阈值后停用并写一条运行记录，走现有的定时任务完成提醒。不加最短间隔，不加任务数量上限。

## 4. 值得新增的功能

### 4.1 主动建议

OpenMuse 的 Ideas 是一组带来源的建议：扫描邮件和目标，命中规则就生成一条（标题、理由、证据、可直接执行的 prompt），已回复或已完成的来源会被排除，建议 id 由内容哈希得出，重复扫描不会堆出重复条目。界面上可以采纳、改一句再采纳、或忽略。采纳时用 `compareAndSwap` 抢占，并发的另一次采纳不会建出第二个任务。刷新每 15 分钟一次，失败时给一条通知而不是静默。

Jeff 已经有定时任务、项目群看板、记忆和插件指令这些结构化数据，缺的是「从这些数据里长出一条建议」。

建议做成小杰的一个只读动作，不新建页面：小杰定期看最近失败的定时任务、看板里停留过久的任务、反复出现的同类指令，整理成几条带证据的建议，显示在小杰会话顶部，采纳就变成发给对应智能体或项目群的一条消息，忽略就记下来不再提。建议的生成规则先用确定性代码，不靠模型发挥。

### 4.2 网页监控

OpenMuse 的 Monitor 盯一个公开页面，条件是内容变化、出现某段文字、或价格低于阈值，按分钟间隔复查，命中后发一条去重过的通知，失败会退避。检查动作复用同一个浏览器 worker。

Jeff 的定时任务能做这件事，但要手写 prompt 和 cron。建议在定时任务上加一个「监控」模板：填地址、条件、频率，到点由调度器打开内置浏览器读页面并比对上次结果，有变化才发消息，没变化只记一条运行记录。比对和去重放在调度器里，不交给模型判断。

### 4.3 PDF 表单

OpenMuse 用 `pdf-lib` 读 AcroForm：校验文件头、拒绝加密和 XFA、限制 10MB 和 500 页，逐字段抽出名称、当前值和类型，填充时只写用户给过的值，输出前剥离 PDF 里的动作入口。表单往返是一条持久任务：导入、缺字段时停下问人、生成填充副本、准备回复。

Jeff 目前把 PDF 当文件链接交给模型和外部工具。建议先做最小的一块：内置浏览器或文件卡片里对 PDF 提供「读取表单字段」，结果以结构化列表回到会话，填充仍然由人确认后的工具调用完成。扫描件 OCR 不在这一步里。

## 5. 明确不借鉴的部分

- **两阶段审批**。OpenMuse 的 `ActionService` 把发邮件、改日历做成提案：带 SHA-256 哈希、30 分钟过期、批准前校验任务仍在运行。这套机制服务的是「助理可能对外发送」的场景。Jeff 的工具作用在本机，用户要的是直接执行；风险控制继续靠现有的工具权限询问，不引入提案、哈希校验和批准门禁。
- **独立的浏览器 worker 与 Docker 电脑**。Jeff 的 webview 和本机工作区已经是人和智能体共用的同一处，拆进程会让「接管」变成「看另一台机器的屏幕」。
- **CopilotKit Intelligence 托管会话**。Jeff 的会话在本地库里，同步走 WebDAV，不外发。
- **邮件、日历、Google 账号连接**。不在 Jeff 的产品范围内。

## 6. 落地顺序建议

1. 生成期间的消息队列（纯前端，风险最低，立刻能感到差别）。
2. 浏览器与文件的工具结果卡片（展示层，不改协议）。
3. 定时任务连续失败自动停用（调度器内的小规则）。
4. 网页监控模板（复用定时任务和内置浏览器）。
5. 主动建议（依赖前面几项沉淀的运行数据）。
6. 项目群派发的工具调用幂等（改动面最大，最后做）。
