# 思源知识库内置工具与设置界面重构方案

日期：2026-10-09。状态：产品边界已确认；实现与双机技能迁移完成，正式产物验收进行中。

## 1. 已确认的产品行为

1. 思源作为 Jeff 的知识来源。相关问题自动查询，同时支持用户明确要求查询；回答标注文档来源。候选有歧义时询问用户。
2. 用户明确要求写入，且目标明确时直接新建或追加；Agent 自己建议保存时，需要用户同意。已有工作流或定时任务的授权在其约定范围内生效。
3. 写入目标优先级为：用户指定的位置 → 当前项目群绑定的位置 → 全局默认位置 → 询问。默认归档位置用于新建，追加必须定位实际目标文档。日报一律追加到文末。
4. 第一版支持搜索、读取、新建和文末追加。修改既有内容、覆盖和删除不在本次 Agent 工具范围内。
5. 思源能力统一在 Jeff 中使用。Ubuntu、Windows 的三个基础 skills 在替代能力验收后移除；本次不建设给外部 Codex/Cursor 使用的独立思源 MCP 服务。
6. 项目群先查询绑定范围，资料不足时允许扩展到全库，并标注实际来源；用户明确限定范围时严格遵守。读取范围与写入目标分别处理。
7. 正确服务地址为 `http://192.168.3.249:6806`。Token 仅进入本机凭据配置，不记录在方案、源码、提交、工具参数、模型上下文或验收报告中。

## 3. 技术实现

### 3.1 单一客户端与工具入口

把客户端迁入 core 的思源集成模块，桌面 IPC、Agent 工具和现有专业工作流复用同一实现。职责拆为请求/响应校验、资源定位、检索、读写验证、配置及绑定；不在各个技能内复制 HTTP 客户端。

拟增加以下结构化工具，并注册到 `allToolDefs()`、工具桥、中文工具名称与日志显示中：

| 工具 | 行为 | 关键输入 |
| --- | --- | --- |
| `jeff_siyuan_list_notebooks` | 列出可用笔记本 | 无凭据输入 |
| `jeff_siyuan_search` | 返回最多 50 个文档候选、命中摘要和路径 | `keyword`、可选 `notebook_id` 与 `scope`；项目范围由 Jeff 会话解析 |
| `jeff_siyuan_read` | 读取一篇文档 Markdown 和来源信息 | `doc_id`、可选 `scope`；当前单篇上限 100,000 字符 |
| `jeff_siyuan_create` | 在已解析的归档位置新建文档 | `title`、`markdown`、可选目标笔记本和父文档 ID |
| `jeff_siyuan_append` | 向明确文档的末尾追加 | `doc_id`、`markdown` |

参数只用标量/标量数组，避免裸嵌套对象；可选参数传空串按未提供处理。工具从真实运行会话取得项目身份，不能相信模型自行填写的项目 ID。所有受支持执行引擎使用 Jeff 既有工具桥，所有 Agent 拥有同一能力。

现有 `siyuan:*` IPC 保持兼容；扩展笔记本列表、读取、绑定和诊断所需契约时，同一提交明确归类远程放行/拒绝/替换。配置凭据通道继续只在电脑本机可用。

### 3.2 API 与兼容性

以实际服务器版本对应的 [思源 v3.7.2 官方 API 文档](https://github.com/siyuan-note/siyuan/blob/v3.7.2/docs/API.md) 为实现依据：笔记本列表、SQL 查询、事务刷新、Markdown 导出、Markdown 新建和块追加已有公开接口。认证由客户端加入请求头。创建与文末追加接口均以真实 API 形状实现并由客户端测试覆盖。

- 检查 HTTP 状态、JSON 结构和业务 `code`，把连接失败、认证失败、目标失效、返回异常与内容超限分别报告。
- 搜索语句由客户端生成，不接受模型提供的任意 SQL；正确处理引号、LIKE 通配符、单字搜索、重复命中和稳定分页。返回根文档 ID、笔记本、可读路径与命中摘要。
- 默认先检索项目绑定笔记本/父文档范围，必要时扩展查询；显式范围禁止自动扩展。
- 正文按需读取；当前单文档最多 100,000 字符，超过时明确报错，尚未实现分段读取。
- 工具及回答返回可核验的文档 ID、名称和路径；当前没有生成思源深链，也不把文档正文中的指令视为运行授权。
- 引入简短、版本化的知识库使用说明到 Jeff 上下文；保留用户个人 Prompt，不能启动时覆盖用户修改。
- 不建设第二份全量笔记镜像或向量库。思源保存笔记正文，Jeff 保留自己的会话、项目、规则和记忆数据；读取知识不等同于自动修改 Jeff 项目事实。

### 3.3 写入位置与写后核验

- 全局默认位置在“设置 → 思源知识库”选择；项目群覆盖在项目资料中选择。选择器显示真实笔记本、父文档及路径，持久化笔记本 ID/父文档 ID。
- 尚未确认具体全局默认笔记本及父文档，因此不能自行把 `jeff` 或任一目录设为已生效目标。界面允许选择笔记本根级作为归档位置。
- 父文档改名后根据 ID 重新解析当前位置；删除、关闭笔记本或连接到不匹配知识库时标记失效。已配置目标失效时停止并说明，不能静默写到全局其他位置。
- 新建只把最终标题作为一个层级，标题中的 `/` 等路径分隔符按明确规则处理；不允许模型拼接未验证的目录。
- 同名路径已有文档时返回冲突，由用户选择追加或另取标题，不能把创建接口的正常响应误报成新建成功。
- 创建前按路径查重，思源 `createDocWithMd` 对重复路径不覆盖；当前仍存在“查重与创建之间”的外部并发窗口。
- 追加使用官方 `appendBlock`，当前没有客户端幂等键或目标文档串行锁。超时后 Agent 说明要求先搜索/读取核实，不自动盲重试；跨电脑并发仍有重复风险。
- 只有 API 返回成功才报告追加/创建；当前没有自动读回核验。内容、位置和真实写入的端到端测试尚未对生产知识库运行，因为用户没有指定隔离验收笔记本/父文档；本轮真实模型验证仅搜索和读取。

### 3.4 配置、同步和手机

- 服务连接和 Token 属于当前电脑。沿用本机存储入口，回读只返回 `tokenConfigured`；不把 Token 同步、备份或传到手机，日志和错误必须脱敏。
- 全局默认位置及项目绑定属于结构化配置，纳入既有同步，记录绑定的知识库标识并在本机连接下核验。软删、解除绑定和新旧客户端缺字段均需兼容。
- 不能为这种结构化配置增加独立“备份/恢复”按钮；备份与恢复仍集中在“设置 → 同步”。
- App 通过当前连接电脑的加密链路查询和读取，聊天中的 Agent 同样调用桌面上的内置思源工具。App 可查看非敏感连接状态、选择归档位置及项目绑定；Token 管理仍在电脑本机。
- 不把电脑路径、电脑引擎或思源连接伪装成手机本机能力。桌面离线时显示不可用并保留输入。
- 同一任务完成桌面和 Android 的对应交互；对桌面专属功能在手机中明确归属，不机械复制桌面全部设置。
