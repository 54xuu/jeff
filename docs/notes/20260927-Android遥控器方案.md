# Jeff Android 遥控器方案（电脑为主，App 远程控制）

2026-09-27 定稿。本文件是可直接执行的 Plan，后续各期开发以此为准；执行中改了决定，回来改这份文件。

## 1. 目标与边界

- **电脑是唯一的「大脑」**：数据（`jeff.db`、会话、记忆）、模型调用、工具执行、工作空间文件全部留在电脑上。
- **App 是远程界面**：在外面用手机看电脑上所有会话、发消息、切会话、选电脑上的目录、管理智能体/项目群/定时/插件，功能与桌面端一致。
- **绑定关系**：1 台电脑只能绑定 1 个 App；1 个 App 可以绑定多台电脑。
- **不做**：手机本地跑模型；手机上的「离线发消息排队」（电脑离线时只读）；iOS。

## 2. 已定的八项决策

| 项 | 决定 |
|---|---|
| 仓库 | 同一个 `jeff` 仓库，新增 `apps/mobile`、`apps/relay`，共用 `AGENTS.md` 与接口契约 |
| App 技术栈 | React + Capacitor 打包 Android，界面按 WeUI（微信官方设计规范） |
| 后台通知 | Android 常驻前台服务保持连接，不接厂商推送 |
| 电脑离线 | 显示「电脑离线」，可只读浏览手机上缓存的会话 |
| 会话语义 | 手机与电脑共享同一个「当前会话」（真·遥控器） |
| 安全 | 扫码配对 + 端到端加密（中转站只见密文）+ App 指纹锁 |
| 中转站地址 | `47.106.209.32` + 自签证书，App 内置证书指纹校验 |
| 范围 | 分三期交付（见第 7 节） |

## 3. 总体架构

```
┌──────────── 家里电脑 ────────────┐          ┌──── 阿里云 ECS ────┐          ┌──── 手机 ────┐
│ 渲染层 ⇄ ipcMain handlers 表      │          │  jeff-relay        │          │  Jeff App     │
│            ▲                      │  WSS     │  （只转发密文，    │   WSS    │  （React +    │
│   RemoteGateway（新增）───────────┼────────▶ │   存绑定关系）     │ ◀────────┼  Capacitor）  │
│   同一张 handlers 表 + bus 事件    │  出站    │  :9443             │          │  前台服务     │
└───────────────────────────────────┘          └────────────────────┘          └───────────────┘
```

**核心思路**：桌面端渲染层与核心之间只有两个口子：`invoke(channel, payload)`（`apps/desktop/src/preload/index.ts`）和 `jeff:push` 事件（`apps/desktop/src/main/index.ts` 的 `broadcast`）。主进程把全部功能注册成一张 `handlers` 表（`apps/desktop/src/main/ipc.ts` 的 `registerIpc`）。因此：

1. 把 `handlers` 表从 `registerIpc` 里导出，本地 `ipcMain` 和远程网关**共用同一张表**，远程能力天然与桌面一致，不维护第二套业务代码。
2. 远程网关订阅与 `broadcast` 相同的 `core.bus` 事件，推给已连接的 App。
3. App 端实现一个与 `window.jeff` 同形的 `RemoteJeff`（`invoke` + `onPush`），界面层按 channel 调用，与桌面渲染层写法一致。

**为什么需要中转站**：电脑在家庭 NAT 后、手机在 4G 网络，两端都无法被直接访问；两端都主动出站连 ECS，由中转站按绑定关系配对转发。

## 4. 三个组件

### 4.1 中转站 `apps/relay`（部署在 ECS）

- Node 22 + `ws`，单进程；持久化用一个 SQLite 文件（`node:sqlite` 或 `better-sqlite3`），只存：
  - `desktops(desktop_id PK, sign_pubkey, name, created_at, last_seen_at)`
  - `apps(app_id PK, sign_pubkey, name, created_at, last_seen_at)`
  - `bindings(desktop_id PK/UNIQUE, app_id, created_at)` —— **`desktop_id` 唯一 = 1 台电脑只能绑 1 个 App**；`app_id` 不唯一 = 1 个 App 多台电脑
  - `pairing(token PK, desktop_id, expires_at)`：一次性、5 分钟过期
- 身份认证：连接时中转站下发随机 challenge，客户端用 Ed25519 私钥签名；中转站只保存公钥，不保存任何口令。
- 只转发：按 `desktop_id` 在「电脑连接」与「App 连接」之间转发**密文帧**，不解密、不落盘消息内容。
- 在线状态：电脑上下线时通知已绑定的 App（`presence` 帧，明文，仅含 `desktop_id` 与在线与否）。
- 限流与上限：单帧 ≤ 4 MB（图片需先在 App 端压缩），每连接速率限制，防止被当成公网转发器滥用。
- 部署：`/opt/jeff-relay` 用 Docker Compose，`restart: unless-stopped`，宿主机端口 **9443**（443 已被 WebDAV 占用，互不干扰）；自签证书 SAN 为 `IP:47.106.209.32`，证书 SHA-256 指纹写进 App 与桌面端配置用于固定校验。需要在阿里云安全组放行 TCP 9443。
- 资源预估：常驻内存几十 MB。ECS（`ecs.e-c1m1.large`，实测可用内存约 1.2 GiB、磁盘余 33 GB）完全够用；瓶颈是**公网带宽**，需在控制台确认带宽档位。

### 4.2 桌面端远程网关（`packages/core` + `apps/desktop/src/main`）

- 新模块 `apps/desktop/src/main/remote/`：
  - `gateway.ts`：维持到中转站的出站 WSS（断线指数退避重连）；收到 App 请求 → 解密 → 白名单校验 → 调 `handlers[channel](payload)` → 加密回包。
  - 订阅 `data-changed` / `chat-updated` / `chat-stream` / `group-updated` / `cron-updated` / `cron-turn-done` / `sidecar-status`，转发给 App。
  - **`chat-stream` 增量化**：现在每次推送的是累计全文（`packages/core/src/index.ts` 约 1513 行），走公网改为「偏移量 + 增量文本」并按 150–200 ms 合并，`done` 帧附全文校验长度。
- **通道白名单**（放在 `packages/core/src/remote/`，可单测）：
  - 放行：绝大多数数据与聊天通道。
  - 拦截：`smoke:*`、`browser:result` / `browser:state` / `browser:pageShot`（渲染层内部回传）、`notify:desktop`、`debugLog:openDir`。
  - 替换：`dialog:pickDir` → 新增 `fs:listDirs`；`fs:openPath` → App 端改为预览或下载；`plugin:import`（弹原生对话框）→ 强制传 `dir`，配合 `fs:listDirs`。
- **新增通道**（写进 `packages/core/src/ipc/contract.ts`，桌面与 App 共用类型）：
  - `fs:listDirs { dir? }`：不传时返回根（Windows 盘符列表 / Linux 的 `/` 与家目录 + 常用目录），传了返回子目录（只列目录）。
  - `fs:mkdir { dir }`：选目录时可新建。
  - `fs:readBinary { file, offset, length }`：分块读取，用于手机预览图片、下载产物（二期）。
  - `remote:status` / `remote:pairStart` / `remote:pairConfirm` / `remote:unbind` / `remote:settings`：桌面端「设置 → 远程控制」使用。
- **共享当前会话**：手机调用 `session:activate`、`chat:new`、`group:threadNew` 等改动类通道后，网关补发对应事件，让桌面界面跟着切过去；桌面端操作同理推给手机。
- **电脑保持可控**：「设置 → 远程控制」新增两个开关：开机自启（`app.setLoginItemSettings`）、远程已绑定时阻止系统睡眠（`powerSaveBlocker`）。在外面控制家里电脑，电脑睡着就什么都做不了。
- 协议版本：契约里加 `REMOTE_PROTOCOL = 1`，握手时比对，不兼容时 App 提示升级。

### 4.3 Android App `apps/mobile`

- React 19 + Vite + Capacitor 7；状态管理沿用 zustand；复用 `packages/core/src/ipc/contract.ts` 的类型、桌面端的 Markdown 渲染与格式化工具（能直接复用的抽到共享位置，不复制粘贴）。
- **界面（参照微信）**：
  - 底部四个 Tab：**消息**（私聊 + 项目群按最近更新混排）、**通讯录**（智能体按分组折叠 + 项目群）、**发现**（定时任务、插件、任务看板）、**我**（我的电脑、绑定管理、设置、指纹锁）。
  - 「消息」顶栏显示当前电脑名 + 在线圆点，点击下拉切换电脑（多台电脑时）。
  - 聊天页：微信式气泡；流式回复中的工具步骤折叠成一行；长按消息出菜单（复制 / 停止）；输入框右侧「+」面板：相册、拍照、插件 `/` 指令、切换会话。
  - 项目群资料页 / 智能体资料页：参照微信「聊天信息」页的分组列表。
  - 工作空间目录：「选择电脑上的目录」弹出远程目录浏览器（面包屑 + 子目录列表 + 新建文件夹）。
  - 亮色 / 暗色跟随系统，品牌色与桌面端 `weui` 主题包一致。
- **原生能力（Capacitor 插件）**：扫码（配对）、相机 / 相册、Android Keystore 安全存储（私钥与共享密钥）、指纹解锁、本地通知、**前台服务**。
- **后台通知**：前台服务在 Kotlin 侧自己维持一条到中转站的连接（WebView 进后台会被冻结，不能靠 JS 保活），只接收「回复完成 / 定时任务完成 / 权限待确认」这类通知帧并弹本地通知；点通知拉起 App 进入对应会话。Kotlin 侧需要实现同一套加密（见第 5 节，选型保证 JS 与 Kotlin 都有成熟实现）。
- **离线缓存**：会话列表、各会话最近消息按 `desktop_id` 缓存到本机 SQLite（`@capacitor-community/sqlite`）；电脑离线时只读展示并标注「最后同步于 xx」。
- 版本：`apps/mobile/package.json` 与仓库同一版本号，Android `versionName` 取自它，`versionCode = major*10000 + minor*100 + patch`。

## 5. 配对与端到端加密

**身份密钥**：电脑和 App 各自首次启动时生成两对长期密钥：Ed25519（向中转站证明身份）与 X25519（与对端协商密钥）。私钥只存本机（电脑存 `~/.jeff` 下 0600 文件或 kv 加密项；手机存 Android Keystore 保护的安全存储）。

**配对流程**：

1. 电脑「设置 → 远程控制 → 绑定手机」：向中转站注册并申请一次性 `pairing token`（5 分钟有效），界面显示二维码，内容为 `{relay: "wss://47.106.209.32:9443", certSha256, desktopId, desktopName, desktopX25519Pub, token}`。
2. App 扫码 → 校验证书指纹 → 带自己的公钥与 token 向中转站申请绑定。
3. 电脑弹出确认框「手机 XXX 请求绑定」，并显示双方公钥派生的 6 位安全码，手机上显示同一串，**用户在电脑上点确认才生效**（防止二维码被偷拍后被抢先绑定）。
4. 中转站写入 `bindings`；若该电脑已有绑定，拒绝，除非电脑端先「解除绑定」或在确认框里选「替换原有手机」。
5. 解绑：电脑端、App 端都可发起；电脑端解绑后该 App 的公钥立即失效（手机丢了在电脑上解绑即可）。

**会话加密**：每次连接双方用 X25519（长期 + 临时密钥）协商，经 HKDF-SHA256 派生会话密钥，帧用 AES-256-GCM 加密，带递增序号防重放。选这组算法的原因：JS 端用 `@noble/curves` + `@noble/ciphers`（纯 JS、无原生依赖，桌面与 WebView 同一份代码），Kotlin 端用 BouncyCastle 或 Tink 都有现成实现。电脑端只接受已绑定 App 公钥发来的请求，即便中转站被攻破，攻击者也既读不到内容，也发不出能被电脑接受的指令。

**App 指纹锁**：打开 App 或从后台回来超过 N 分钟需指纹 / 锁屏密码解锁；解锁后才解开 Keystore 里的密钥。

## 6. 仓库与协作约定

### 6.1 目录

```
apps/desktop    # 现有桌面端 + main/remote/ 远程网关
apps/mobile     # 新增：React + Capacitor，android/ 为 Capacitor 生成的原生工程
apps/relay      # 新增：中转站 + Dockerfile + compose
packages/core   # 现有核心；新增 src/remote/（协议帧、加密、白名单，三端共用）
```

`packages/core` 里给 App 用的部分必须无 Node 依赖（与现有「渲染层别名到 `contract.ts`」的做法一致）。

### 6.2 `AGENTS.md` 需要追加的规则（〇期落地）

- **版本号**：一致性检查从五处扩到含 `apps/mobile/package.json`、`apps/relay/package.json`，`packages/core/tests/version.test.ts` 同步扩展。
- **收尾产物**：由「deb + exe」变为「deb + exe + apk」；中转站有改动时再加「部署 relay」。
- **契约先行**：新增或修改任何 IPC 通道时，同一提交内决定它在远程白名单里是放行、拦截还是替换，并补白名单单测；否则 App 调不到或误放行本机专属能力。
- **一个功能两端做**：涉及界面的新功能，默认在同一次任务里同时做桌面端和 App 端；只做桌面端时必须在总结里写明 App 端待办。
- **真机调试**：`adb connect 192.168.3.161:5555`；安装与截图命令写进 AGENTS.md。
- **签名密钥**：release keystore 放仓库外（如 `~/.jeff-android/release.keystore`），口令存 ZCode 记忆，禁止进仓库。

## 8. 测试方案（对齐 AGENTS.md 三层）

- **单测（必跑）**：协议帧编解码、加密互通测试向量、白名单（每个 IPC 通道都必须有归类，新增通道未归类即失败）、`fs:listDirs`、流式增量合并；中转站的配对、唯一绑定、转发、离线、限流。
- **封闭 E2E（无模型）**：本地起中转站 + `launchJeff` + 一个 Node 版「假手机」客户端（复用 App 的协议客户端代码）完成配对并调用通道，断言服务端事实（DB 真的变了、桌面界面跟着切换了会话）；App 的 Web 构建在 Playwright 里以 390×844 视口跑界面用例并截图人工目检。
- **真实模型 E2E（聊天类改动必跑）**：从「假手机」发私聊 / 群聊，核对流式期间所见在落库里都能找到、桌面与手机两边显示一致。
- **真机**：`adb install -r` 后用 `adb exec-out screencap -p` 截图留档到 `.tmp/`，人工目检布局、暗色、长消息与键盘遮挡；验证后台通知与断网重连。
- **产物验证**：deb / exe 按现有规则；apk 用 `apksigner verify` 校验签名、`aapt dump badging` 核对 `versionName`。

## 9. 风险与待确认

- **公网带宽**：需在阿里云控制台确认 ECS 带宽档位；图片发送前压缩到长边 1600 px 左右，文件下载分块。
- **国产 ROM 杀后台**：前台服务仍可能被杀，App 需提供「电池优化白名单」引导页；最坏情况退化为打开 App 时补拉。
- **电脑必须开机且 Jeff 在运行**：已用开机自启 + 防睡眠缓解，远程唤醒（Wake-on-LAN）不在本期范围。
- **并发操作**：手机与电脑同时在同一会话发消息时，以核心现有串行语义为准（后发的排队或提示「正在回复中」），在一期封闭测试中覆盖。
- **自签证书**：换 IP 或证书到期时需要重新配对或下发新指纹；证书有效期设 10 年，指纹变更走 App 内提示。
