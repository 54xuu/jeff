## 1. 基座选型：opencode sidecar

对比过三个候选：

| 候选 | 优势 | 短板 |
|---|---|---|
| opencode（anomalyco/opencode，MIT，TS+Bun） | client/server 分离（HTTP+SSE+OpenAPI）；MCP 一等公民（local/remote+OAuth）；Skill 兼容 `.claude` 生态；多 agent md/json 定义；75+ provider（AI SDK+models.dev）；权限审批体系 | 重型单体；上游迭代快；Windows 官方推荐 WSL（CLI 可原生跑） |
| pi（earendil-works/pi，MIT，TS） | 干净的无头库（pi-ai + pi-agent-core），会话树 JSONL 优雅 | MCP 哲学上拒绝需自建；多 agent 编排、权限全自建；server 层 0.x 实验态 |
| Vercel AI SDK 纯自建 | 最自由 | 一切从零，工作量最大 |

**结论：opencode sidecar**。桌面应用 spawn `opencode serve` 子进程，`@opencode-ai/sdk` 等价物（自写薄客户端）驱动。MCP/Skill/多 agent/provider/权限白拿。

### 本机验证结论（opencode 1.18.26）

- 隔离目录：`XDG_CONFIG_HOME` / `XDG_DATA_HOME` 指向 Jeff 私有目录即可，完全不碰用户全局 `~/.config/opencode`（本机全局配置有用户在用的 MySQL MCP 和 skills，绝不能动）。
- 配置文件 `opencode.json`：`provider` 内联声明 openai 兼容自定义 provider（`npm: @ai-sdk/openai-compatible` + baseURL + models）；`small_model` 等字段为字符串 `"providerID/modelID"` 形式。
- 自定义 agent：`<config>/agent/<name>.md`，frontmatter（description/mode/model/temperature…）+ 正文 system prompt；`GET /agent` 可见。mode 支持 primary/subagent/all。
- 消息 API：`POST /session` 建 session（可带 agent/model）；`POST /session/{id}/message` 发消息（parts + agent + model + system + noReply，可按消息切换 agent）；`POST /api/session/{id}/prompt` steer/queue；`GET /event` 全局 SSE。
- 插件工具：`<config>/plugin/*.js` 导出 `{ tool: { name: { description, args(JSON-schema 形式即可), execute(args, ctx) } } }`，**不需要 zod**，加载无报错，工具可被模型调用、结果正常回流。
- 冒烟方式：本机无任何 LLM 凭证 → 写了一个极简 OpenAI 兼容 mock（SSE + tool_calls）做全链路验证与后续自动化验收。

## 2. 记忆系统：hermes-agent 的设计（要移植的部分）

三层设计，Jeff 取前两层：

1. **curated 记忆**：`MEMORY.md`/`USER.md` 纯 Markdown，条目以 `\n§\n` 分隔；硬字符预算（约 1300 token），超限报错逼模型当场自我整合（merge/删旧），每 turn 最多 3 次失败后放弃；add 有精确去重；replace/remove 用唯一子串匹配；原子写（temp+rename）+ flock 锁；外部漂移保护（文件被改得无法 round-trip 时拒绝写并备份 `.bak`）；安全扫描（prompt injection/凭据/隐形 Unicode）。
2. **会话搜索**：SQLite FTS5（CJK bigram/trigram），`session_search` 工具按需检索，零常驻 token 成本。
3. **外部 RAG provider 插件**：不做，留接口。

**读取**：curated 记忆会话开始时全量冻结快照进 system prompt（prefix-cache 友好，mid-session 写盘不改当轮 prompt）；**写入**：agent 调 memory 工具 + nudge 机制（每 N 个用户 turn 触发后台自省 fork，重放会话快照让模型决定存什么）。
关键源码：`tools/memory_tool_store.py`（MemoryStore）、`agent/background_review.py`（自省）、`tools/session_search_tool.py`、`hermes_state_fts.py`（CJK 分词）。

## 3. 多智能体：multica 的设计（要适配的部分）

- 概念模型：Agent=身份配置；Runtime=机器+CLI；Run=一次执行。Jeff 简化为：Agent=聊天好友（opencode agent），执行就地发生。
- Squad 协作：群主 leader 唯一入口，成员名册 briefing 注入 leader prompt；成员通过 @mention 触发（不是进程内子代理）；成员回报自动唤醒 leader；防自触发回路与去重（`issueguard`）。Jeff 适配为「leader 统筹 + @成员直达」。
- Issue：状态=行为类别（7 内置）+ 优先级 5 级 + assignee（member/agent）+ 编号（如 MUL-123 → Jeff 用 JEF-n）；agent 通过 CLI/API 改状态，服务端不自动翻转（仅 run 失败回滚 todo 一个例外）。
- Project：lead 可为 agent；issue 归属唯一 project；资源绑定（GitHub repo/本地目录）—— Jeff 暂不做资源绑定。
- 关键源码：`server/internal/handler/squad_briefing.go:196`（Roster briefing）、`server/migrations/084_squad.up.sql`、`server/internal/issuestatus/`、`server/internal/issueguard/duplicate.go`。

## 4. 其他决策记录

- 桌面壳：Electron（主进程 Node 直接管 sidecar，electron-builder 出双平台包）；不选 Tauri（Rust 侧重写一遍 SDK/SQLite/sidecar 管理）。
- WebDAV：实体级双向合并（JSON 包 + updatedAt LWW + 墓碑），会话数据不同步。
- 界面：微信式（一个 agent=一个好友，一个项目=一个群；群主 leader 统筹），微信绿 `#07C160`，亮/深夜模式。
- 小杰：内置纯管家 agent（admin 工具，无编码工具），不可编辑，聊天列表置顶。
- 构建：GitHub Actions matrix（windows-latest + ubuntu-latest）→ Releases；tag 触发。
- 执行方式：M1→M4 四阶段一次性连续执行，每阶段自动验收（单测+端到端冒烟+构建产物检查），无人值守。
